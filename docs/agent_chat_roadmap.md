更新日期：2026-10-25。功能状态以当前代码为准；Bing 搜索已实装；未来项目仍按下表区分。

## 已实装的联网搜索

采用模型自主决策 → Python 受限 Bing 查询 → 原 DSH 会话消化 → QQ 最终文本的流程，普通闲聊不增加额外模型调用。用户选择无需额外 Key 的 Bing；当前没有接 DeepSeek Search API，也不会自动复用第三方聊天 Key。配置、额度、缓存、隐私和恢复策略见 [搜索使用说明](agent_chat.md#ai-自主联网搜索bing)。

原 qq-bridge 提供 `web_search` / `web_fetch`，并可通过 DSH 工具循环多次取资料；本项目首版每个回复链仅一次查询，只读取搜索摘要。保留完整 DSH 工具禁用，不调用任意网址、不下载网页正文。Bing RSS 检索质量有限，可能只返回泛化页面；模型需要判断证据是否足够，不将“搜索成功”当成“事实核实成功”。

后续搜索增强可考虑更稳定的独立搜索 API、额外查询轮数和受限网页正文读取。增加前需要分别评估查询外发范围、预算、SSRF 和网页提示注入；不能直接把聊天网关 Key 发给另一个服务商。

上游参考：[搜索实现](https://github.com/Derpyu520/qq-bridge/blob/main/src/web-search.js)、[MCP 包装](https://github.com/Derpyu520/qq-bridge/blob/main/src/mcp-web-search-safe.js)。

## 稳定性后续增强（尚未实现）

当前会捕获 DSH 故障并隔离到 AI 请求，部分阶段会暂停群会话以避免重复发送；完整现状见 [断线与恢复](agent_chat.md#dsh-关闭断线与恢复)。可继续增加：只暂停 AI 的运行时维护开关、全局故障熔断与限频健康探测、经过队列/回合核查的恢复命令、明确区分实时健康与本地状态、日志轮转与脱敏导出。

自动恢复必须能证明旧请求已结束且没有待发送结果；不应仅因端口恢复就自动重放失败消息、解除所有暂停或切换到普通智能体。此处是计划，本轮没有为验证健壮性停止生产机器人或关闭真实 DSH。

## 与原 qq-bridge 相比还差什么

核对日期：2026-10-25；参考上游公开 `main`、README 标注的 `v0.2.1-r1` 及当前源码。下面区分实际功能差距与本项目主动保留的权限边界；原项目不同运行模式行为并不完全相同。

| 能力 | 原 qq-bridge | 当前 agent_chat | 后续判断 |
| --- | --- | --- | --- |
| 角色聊天与持久会话 | 多运行模式、角色注入/读取、分会话持久化 | 已有角色卡、分群会话、自动压缩适配、增量投递 | 核心体验已有；不是所有上游路径都逐轮附完整卡 |
| 联网搜索与正文获取 | `web_search` / `web_fetch`，工具循环可多次查询 | 已有 AI 决策的 Bing 摘要搜索、同会话消化和来源链接 | 尚缺网页全文、多轮检索和更多搜索后端 |
| 等待与自主唤醒 | v2 可取未读消息、长轮询等待、设置潜水和唤醒条件 | 2 秒合并、10% 可配置抽签、按闲置时间主动开口 | 尚缺模型选择等待对象、条件和时间，以及更完整的参与状态机 |
| 独立长期记忆 | v2 有话题、待表达想法、成员印象的持久化工具 | 依靠 DSH 历史和压缩摘要 | 缺可管理的结构化记忆；现有会话记忆不等于永久事实库 |
| 黑话/梗学习 | 查询、提交候选词条、检索研究与人工确认 | 人设知识和聊天上下文接梗 | 缺词库、候选审核和积累机制 |
| 图片与更多消息类型 | 图片/表情兜底、按消息取图、合并转发读取等 | 当前/引用/近期图片；动态图首帧；其他类型多为占位符 | 缺合并转发展开、更多表情兜底和按需精细取图 |
| QQ 表达动作 | 模型可分多条发送、主动选择引用、戳一戳、发送/收藏表情 | 每次最终回复只发普通文本，能理解输入引用 | 缺主动引用和表情等互动动作，不能靠模型输出 CQ 码解锁 |
| 语音 | 有受限语音库发送；转写相关能力依赖网关，部分语音工具已独立拆出 | 听语音延期，AI 发语音未接入 | 不能把上游“发语音”当成已具备通用语音识别或音色理解 |
| 设置与角色管理 | 本地 Web 控制台、角色编辑/切换、模式切换、分会话初始说明 | 私有 env + Markdown + 安装器；`ai 状态/重置` | 缺网页控制台、角色热切换和每群独立设定入口 |
| 用量与费用 | 有 token、缓存与费用看板 | 只有请求额度、状态和日志；暂无用量报表 | 可后续读取 DSH 用量投影；应区分字符、token、缓存和实际账单 |
| QQ 控制宿主 | `closed-agent` 等路径可面向 owner 开放完整工具、审批与控制命令 | 所有聊天会话拒绝工具及控制命令透传 | 有意不移植到群聊桥接，不以功能追平为由放开主机权限 |

优先顺序建议：等待/自主唤醒 → 结构化记忆与黑话 → 表情/引用等互动 → 用量看板与设置界面。语音识别继续遵循延期决定。

对照依据：[上游功能说明](https://github.com/Derpyu520/qq-bridge#readme)、[QQ 工具实现](https://github.com/Derpyu520/qq-bridge/blob/main/src/mcp-snowluma-safe.js)、[桥接实现](https://github.com/Derpyu520/qq-bridge/blob/main/src/bridge.js)、[黑话学习](https://github.com/Derpyu520/qq-bridge/blob/main/src/slang-learner.js)。上游文档索引中有部分文件未出现在公开仓库；涉及语音等能力时以可读取的实现为据，不把缺失说明中的设想列为已验证能力。
