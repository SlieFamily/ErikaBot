## 联网搜索建议方案（未实装）

### 采用桥接管理的只读搜索

建议保持“DSH 负责角色对话，NoneBot 负责能力边界”的分工：模型提出查询需求，Python 桥接验证并调用固定搜索后端，再把有限资料交回原群的 DSH 会话，由绘梨花自然回答。DSH 预设仍拒绝 shell、文件、MCP 和子代理，不需要为联网恢复通用智能体权限。

首版优先评估 DeepSeek 的独立 Search API，而不是每次为搜索另开一个角色智能体：官方已公开 `POST https://api.deepseek.com/v1/tools/search`，可直接返回结构化结果；另有 `/v1/tools/fetch` 用于网页正文。这是截至本次核对的官方接口信息，是否对实际账号或第三方网关可用仍需独立联调确认。[官方 Search & Fetch 指南](https://api-docs.deepseek.com/guides/search/)、[Search 接口定义](https://api-docs.deepseek.com/api/search/)

原 qq-bridge 的当前实现用 Anthropic 兼容 Messages 请求携带服务端搜索工具，再提取搜索结果；同时支持 Bing 回退。可借鉴其结果归一化、超时与缓存设计，但本项目不直接照搬凭据读取和工具开放方式。[上游搜索实现](https://github.com/Derpyu520/qq-bridge/blob/main/src/web-search.js)、[上游 MCP 包装](https://github.com/Derpyu520/qq-bridge/blob/main/src/mcp-web-search-safe.js)

### 一次搜索如何完成

1. **直接查询。** 群友明确说“搜一下 / 查一下”，且通过白名单、命令仲裁、限流等检查时，先做搜索，再让原 DSH 会话回答；能明确提取查询时不多加一次模型判断。
2. **按需查询。** 普通话题进入模型后，如果需要核实近期信息，允许模型给出严格、完整的结构化搜索请求。它是桥接内部控制消息，不发到 QQ；仅接受固定动作与查询词，不能指定程序、文件、API 路径或服务地址。无查询需求的普通闲聊维持一轮调用，不增加独立的“是否搜索”模型。
3. **受限执行。** 对搜索请求进行长度、敏感内容、预算和群范围检查。建议首版每个回复链最多一次搜索，最多取 3 条，查询限制在 120 个字符内。搜索接口接受至多 128 个 Unicode 字符，调用层需按实际接口校验。[官方查询字段](https://api-docs.deepseek.com/api/search/)
4. **回填来源。** 对返回结果生成桥接自己的来源编号，保留标题、网址、摘要、发布时间（可能缺失）与检索时间。首版默认不取整页正文；摘要合计控制在约 3000—4000 字符内，去重并截断。结果作为不可信资料只补入一次，不随每轮聊天反复重发。
5. **自然回答。** 同一角色会话据资料继续回答，热点结论尽量附 1—2 个可核验来源。来源链接从桥接保存的结果中选取，不能把模型临时编造的网址当作已查证来源；没查到、超时或来源冲突时据实说明。

结构化请求需要专门的输出协议与解析测试，不能在模型普通文字中随便匹配“搜索”两个字就执行。应仅在对应阶段接受完整结构，思考标签清理后再解析；异常结构停止内部流程，控制信息不能作为普通回复泄露。

### 凭据、隐私与网络边界

- **凭据绑定服务商。** DSH 中已能聊天，不代表现有 Key 有独立 Search API 权限，也不代表第三方网关的 Key 可发给 DeepSeek 官方。实施时明确选择后端与对应搜索凭据；优先用私有环境配置，不扫描 DSH 的全部凭据，不把 Key 或 Cookie 交给模型。若以后复用已命名的凭据引用，必须显式绑定允许的服务地址。
- **最少外发。** 只向搜索服务发送查询需要的公开主题，不发送整个人设、完整聊天记录、QQ 群号/账号、内部路径或凭据。检测与过滤不是绝对隐私保证；对难以安全提炼的内容拒绝自动搜索。随机接话和自主发言的自动搜索建议首版关闭，先对直接提问启用。
- **固定目的地。** 搜索服务地址由管理员固定，凭据只发送到该允许的 HTTPS origin；拒绝带用户名密码的 URL 与重定向。不要因“同样是 HTTPS”就给任意域名发送 Key。不能把本机 DSH Cookie 当作搜索认证。
- **网页是数据。** 网页里的“运行代码、修改规则、上传文件、再搜索某个秘密”等指令没有管理权限，也不触发递归搜索。清理脚本或 HTML 有助于减少噪声，但真正的边界由桥接允许的动作集合与 DSH 工具守卫承担。
- **首版不做任意 URL 抓取。** 只接收搜索接口的结构化资料，不访问群友任意提供的网址。后续增加正文抓取时，再实现公网 DNS 校验、固定已校验地址连接、重定向逐跳复核、字节/解压/时间上限、仅文本内容，不使用带登录态浏览器。
- **后端回退需配置。** 不因一个服务失败就静默把群聊查询发给另一家。Bing 等备用后端仅在管理员明确配置后启用。

### 成本、并发与恢复

建议独立设置每群搜索额度、全局搜索并发、20 秒总超时和短缓存；缓存按机器人账号、群、查询与后端隔离，热点资料用较短有效期并标出检索时间。首版建议每群每小时最多 6 次搜索，作为待联调的初始值，不是当前代码中的配置。

模型自主提出查询时，通常会多一个 DSH 回合：先提出需求，再读资料作答；这两轮都要计入模型调用预算，搜索费用单独统计，不能藏在原“30 次/小时”额度之外。直接查询应尽量搜索后只调用一次模型。缓存命中也仍有阅读资料的模型输入成本。

搜索流程需要持久化“查询中 / 已取得结果 / 生成中 / 发送中 / 已完成”等阶段，并固定本次输入的消息边界；重启不能重新搜索、重发或跳过期间新到的消息。结果不确定时保留当前停止/暂停策略，不盲目重试。长网络请求采用异步 I/O，与模型并发分别限流，同群仍串行；新消息使自主回复过时时继续丢弃过时发言。

### 验证与实装顺序

1. 先实现模拟搜索后端与严格解析，覆盖普通闲聊不搜索、直接查询、模型请求、沉默、空结果、来源冲突、超时、额度、缓存及跨群隔离。
2. 用测试数据验证网页提示注入、伪造动作、凭据脱敏、SSRF、重定向、大响应和重复投递。确保搜索请求既不能执行程序，也不能改变工具守卫或角色卡。
3. 使用独立 DSH 会话、临时 SQLite 和内存发送器验证真实搜索接口，只用公开测试查询，不发送 QQ 测试消息；此时不停止生产机器人、不改生产 profile。
4. 代码与测试完成后再正式配置搜索凭据和开关，备份后只重启必要进程，先在指定测试群启用，再追加其他允许群。拟议方案无需修改 DSH 工具组成；若需要修改固定对话协议，必须先验证并按预设升级流程安排正式切换。

部署约束见 [保持 QQ 在线的测试与部署](agent_chat.md#保持-qq-在线的测试与部署)。本次只编写方案，没有配置搜索 Key、发起搜索 API 付费测试或开启搜索能力。

## 与原 qq-bridge 相比还差什么

核对日期：2026-10-25；参考上游公开 `main`、README 标注的 `v0.2.1-r1` 及当前源码。下面区分实际功能差距与本项目主动保留的权限边界；原项目不同运行模式行为并不完全相同。

| 能力 | 原 qq-bridge | 当前 agent_chat | 后续判断 |
| --- | --- | --- | --- |
| 角色聊天与持久会话 | 多运行模式、角色注入/读取、分会话持久化 | 已有角色卡、分群会话、自动压缩适配、增量投递 | 核心体验已有；不是所有上游路径都逐轮附完整卡 |
| 联网搜索与正文获取 | `web_search` / `web_fetch` | 尚未实现 | 按上方只读搜索方案优先推进 |
| 等待与自主唤醒 | v2 可取未读消息、长轮询等待、设置潜水和唤醒条件 | 2 秒合并、10% 可配置抽签、按闲置时间主动开口 | 尚缺模型选择等待对象、条件和时间，以及更完整的参与状态机 |
| 独立长期记忆 | v2 有话题、待表达想法、成员印象的持久化工具 | 依靠 DSH 历史和压缩摘要 | 缺可管理的结构化记忆；现有会话记忆不等于永久事实库 |
| 黑话/梗学习 | 查询、提交候选词条、检索研究与人工确认 | 人设知识和聊天上下文接梗 | 缺词库、候选审核和积累机制 |
| 图片与更多消息类型 | 图片/表情兜底、按消息取图、合并转发读取等 | 当前/引用/近期图片；动态图首帧；其他类型多为占位符 | 缺合并转发展开、更多表情兜底和按需精细取图 |
| QQ 表达动作 | 模型可分多条发送、主动选择引用、戳一戳、发送/收藏表情 | 每次最终回复只发普通文本，能理解输入引用 | 缺主动引用和表情等互动动作，不能靠模型输出 CQ 码解锁 |
| 语音 | 有受限语音库发送；转写相关能力依赖网关，部分语音工具已独立拆出 | 听语音延期，AI 发语音未接入 | 不能把上游“发语音”当成已具备通用语音识别或音色理解 |
| 设置与角色管理 | 本地 Web 控制台、角色编辑/切换、模式切换、分会话初始说明 | 私有 env + Markdown + 安装器；`ai 状态/重置` | 缺网页控制台、角色热切换和每群独立设定入口 |
| 用量与费用 | 有 token、缓存与费用看板 | 只有请求额度、状态和日志；暂无用量报表 | 可后续读取 DSH 用量投影；应区分字符、token、缓存和实际账单 |
| QQ 控制宿主 | `closed-agent` 等路径可面向 owner 开放完整工具、审批与控制命令 | 所有聊天会话拒绝工具及控制命令透传 | 有意不移植到群聊桥接，不以功能追平为由放开主机权限 |

优先顺序建议：只读联网搜索 → 等待/自主唤醒 → 结构化记忆与黑话 → 表情/引用等互动 → 用量看板与设置界面。语音识别继续遵循延期决定。

对照依据：[上游功能说明](https://github.com/Derpyu520/qq-bridge#readme)、[QQ 工具实现](https://github.com/Derpyu520/qq-bridge/blob/main/src/mcp-snowluma-safe.js)、[桥接实现](https://github.com/Derpyu520/qq-bridge/blob/main/src/bridge.js)、[黑话学习](https://github.com/Derpyu520/qq-bridge/blob/main/src/slang-learner.js)。上游文档索引中有部分文件未出现在公开仓库；涉及语音等能力时以可读取的实现为据，不把缺失说明中的设想列为已验证能力。
