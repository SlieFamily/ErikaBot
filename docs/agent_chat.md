# agent_chat：NoneBot ↔ DSH 安全角色聊天

NoneBot 负责 QQ 收发、白名单、消息仲裁与限流；DSH 负责模型/API Key、人设、会话持久化与上下文压缩。插件默认关闭。模型凭据只保留在 DSH 内，机器人仅持有本机 DSH 连接凭据。

当前实现面向 Harness **0.2.1-rc.2** 的 slash RPC 与 `remote.mux` 协议（DSH Desktop 2.0.18 内置该版本）。未知响应、缺少安全预设或不支持的接口会停止处理，绝不降级到普通智能体。升级 DSH 后应重新联调。

## 功能与消息优先级

- 默认只响应白名单群内的 @、对机器人的引用回复，以及白名单私聊。普通群聊进入有限本地上下文；将 `AGENT_CHAT_AMBIENT_PROBABILITY` 从 0 调高可允许概率接话，上限 0.2。
- 每个“机器人账号 + 群号/私聊用户”独立绑定一个 DSH 会话，重启复用，避免串群。SQLite 存在 `data/agent_chat/state.sqlite3`，每个对话最多保存 200 条输入；首次补充最近 20 条，以后每次只补充尚未送入 DSH 的最新消息，背景消息单次上限仍是 20 条；已接受的直接提问另行保留，不能被热闹群聊挤出这一窗口。
- 现有显式命令优先。`their_ana.SuperAna` 和 `abuse` 标记为被动处理器：实际发出语录才占用消息。普通消息扫描后不吞掉 AI 机会；默认 @ 时由 AI 接管，关闭 `AGENT_CHAT_TAKEOVER_MENTIONS` 可保留旧 @ 语录行为。
- AI 在 NoneBot 的事件后处理阶段调度，因此不会被 SuperAna 的 `block` 阻断。对 their_ana 的修改不引用 AI 服务，AI 关闭时保留旧行为。
- 同群串行、1 秒合并、2 秒冷却，每小时每个对话最多 60 次调用；最多 2 个模型请求并发、16 个待处理对话，每群一批默认保留最多8条直接提问。默认回复最多 600 字符。
- 收到旧消息快照不重发；输出只认本次请求对应的已完成回合，忽略流式片段和思考内容。断线、超时先清理旧请求并校验会话，确认安全才继续处理新提问；不重试失败请求。发送结果不确定、外来输入或校验失败仍暂停保护。
- 超级用户命令：`ai 状态`、`ai 恢复`、`ai 重置`（也接受 `/ai`，以机器人 COMMAND_START 为准）。重置先清空 DSH 待处理消息并取消执行，再清除当前对话的本地映射与上下文；保留 DSH 历史、独立轻量记忆、共享黑话词库和调用频率记录。

支持文本聊天、可选读图、随机接话和安静时的自主发言。语音和视频目前仍只有类型占位符；语音识别按用户要求延期。可选联网搜索通过 DSH 原生 AnySearch 工具，模型自主决定是否查询；DSH 仍未开放任意文件处理、MCP 或多智能体工具。

### 哪些消息会让她开口

以下规则均先经过白名单、自身消息过滤、去重、旧消息检查和已有插件仲裁：

| 场景 | 是否安排模型调用 | 可能不发言的原因 |
| --- | --- | --- |
| 群内 @ 机器人、引用机器人自己的消息 | 不经过随机概率和夜间静默门槛 | 命令已处理、队列/调用额度/会话状态限制；无法正常回答时给节流后的提示，直接 `[SILENT]` 转为澄清句 |
| 有人戳机器人 | 独立30%机会，AI仍可沉默 | 70%直接略过、去重/冷却/白名单/配额限制；观察期不绕过此概率 |
| 白名单私聊 | 按直接对话处理 | 同样受冷却、调用额度和会话状态限制；失败或直接沉默有简短提示 |
| 普通群消息 | 按夜间开关和 `AGENT_CHAT_AMBIENT_PROBABILITY` 抽签 | 配置值是调度概率，最终回复率还受模型判断及其他限制影响 |
| 发言后观察中的相关新消息 | 同一参与者或引用刚才话题的消息可跳过随机抽签 | 每窗最多3次判断、当前配置1分钟到期；模型可沉默结束观察 |
| 只发图片，没有 @ | 可进入近期上下文；随机接话触发时可能看图 | 不会每张图片立即调用模型；只有明确看图/引用图片的后续提问才重新附带旧图 |
| 群内安静达到阈值 | 定时检查合格群，安排一次自主发言机会 | 无新活动、当天额度用完、无人回应、夜间、模型选择沉默或生成期间有新消息 |

随机接话和自主发言可以输出 `[SILENT]`，表示本次选择不发言，并不要求话题必须与机器人有关。直接 @、引用和允许的私聊若返回 `[SILENT]`，会给一句澄清提示，不再无声略过。普通消息抽签命中后，即使没人 @、群友在互聊，也可以顺着当前话题接梗、吐槽或共鸣；看不懂、不适合插话、话题已过或只能重复尬聊时才选择旁观。不会再次要求模型随机抽签，也不会让每条普通消息都调用模型。当前没有独立的“先判断要不要回复”模型调用；抽签命中后才调用 DSH，由同一轮决定回复或沉默。默认 1 秒消息合并属于去抖，不等于模型自主等待群友把话说完。

随机/主动机会中，模型明确输出 `[SILENT]` 才视为主动沉默。如果确认回合已结束，却没有最终正文（例如服务商只返回 `reasoning` 块），直接 @、引用和允许的私聊会收到一条简短失败提示；随机/主动发言仍保持安静。内部搜索控制输出无法作为答案发布时也适用此规则。不会把思考块或其标签后面的文字提升为答案，也不会因此自动重复模型请求。断线和超时只有清理、结束回合、来源和预设校验全部通过才恢复后续输入；发送结果不确定始终保留暂停保护。

@ 判定会检查原始消息中的结构化提及，避免 OneBot 在处理“引用别人的图片 + @机器人”时删掉 @，使直接提问误走夜间静默或随机路径。消息中间的真实 @ 也有效；@其他人、@全体和文字形式的 CQ 码不会被视为 @机器人。

`AGENT_CHAT_AMBIENT_QUIET_ENABLED=true` 保持原有行为：随机接话也受 `AGENT_CHAT_QUIET_START/END` 影响。设为 `false` 后，夜间时段只约束闲时主动发言（每天6次那一类），随机接话仍按原概率、冷却和配额处理，模型仍可选择静默。当前生产配置为 `false`、静默23:00–09:00、UTC+8、随机概率0.02；修改这些私有配置仅需重启 NoneBot，不需要重启 DSH。

### 发送后观察

设置 `AGENT_CHAT_OBSERVATION_ENABLED=true` 后，机器人成功发出正文或 QQ 表情，会在当前群开启一个观察窗口；默认 `AGENT_CHAT_OBSERVATION_SECONDS=120`、`AGENT_CHAT_OBSERVATION_MAX_CALLS=3`；当前生产配置将观察时间设为60秒。NoneBot 监听新消息，没有消息时不调用模型、不挂起 DSH 回合、不占并发名额。

窗口内，刚才被回复的群友、被安全 @ 的群友继续发消息，或有人引用本轮真实消息时，可跳过配置的随机抽签进入一次续聊判断。模型结合近期增量消息判断是否与刚才话题有关：有话可接就回复，不相关、已结束或无须参与时输出 `[SILENT]` 并结束观察。同一参与者的无关新消息也可能消耗一次判断，但不要求发言。其他群友普通消息按当前2%概率处理。当前没有开放任意等待对象或唤醒条件工具。

观察触发的续聊不延长原窗口、不重置三次预算；到期或次数用尽后回到普通随机接话。新的直接 @ 正常处理，成功发言后可重新开启窗口。简短明确告别会关闭观察。发送失败/结果不确定、只有失败提示、仅贴表情/戳人而未发言，都不会开启窗口；重启、重置及恢复也不会重放旧观察。`ai 状态` 可看剩余时间与次数。

续聊仍受白名单、命令与 `their_ana` 仲裁、队列和每群60轮/小时限制；不计入闲置主动发言的每天6次额度。当前夜间23:00–09:00只停止闲置主动发言，当前2%随机接话和观察续聊照常；观察搜索权限沿用 `AGENT_CHAT_SEARCH_AMBIENT`，后台黑话研究的 AnySearch 权限独立。**本轮未加入“等用户说完”**：原有1秒合并保持不变，不为观察额外推迟首条回复。

### 被戳一戳 / 拍一拍

通过 NoneBot OneBot v11 自带的 `PokeNotifyEvent` 接收通知，只处理目标为当前机器人、发起者不是机器人的事件，沿用 AI 群/私聊白名单。无需 NapCat 自建接口；戳其他人、非白名单、过旧通知都忽略。当前私聊白名单为空时，不会在私聊回应。

默认 **70%直接沉默，不调用模型**；剩下30%进入一次可选回应，AI可简短说话、用emoji/QQ表情、@对方、回戳，也可选择 `[SILENT]`，所以实际出声率可能低于30%。这条概率独立于当前2%随机接话及发送后观察，观察期也不会让每次戳都必回。只使用当前通知中真实观察到的群友作为互动目标；通知没有QQ消息ID，不能被引用或贴消息表情。

重复通知不重新抽签（OneBot没有独立通知ID，同一群/人/目标/秒按同一事件去重）；默认同一对话命中后冷却30秒，冷却内不调用模型，重启不清空冷却。仍受每小时对话额度、队列和会话状态限制，不挤掉已排队的直接提问，也不会发送“处理中”或失败提示。夜间可回应这种用户主动互动，不占每日6次闲置发言额度。本轮不开放搜索、不重新读图，通知不作为群友发言送入后台记忆/黑话整理。已有安全的回戳频控继续适用。

在项目根目录私有 `.env.agent_chat` 中手动调整（不要往已跟踪的 `.env.prod` 写凭据）：

```dotenv
AGENT_CHAT_OBSERVATION_ENABLED=true
AGENT_CHAT_OBSERVATION_SECONDS=120
AGENT_CHAT_OBSERVATION_MAX_CALLS=3
AGENT_CHAT_POKE_REPLY_ENABLED=true
AGENT_CHAT_POKE_REPLY_PROBABILITY=0.3
AGENT_CHAT_POKE_REPLY_COOLDOWN=30
```

观察时长单位为秒，允许30–900秒；例如180表示3分钟。戳回应概率允许0–1，0表示全部静默；冷却允许0–3600秒，0关闭额外冷却。保存后**只需重启 NoneBot**，不需重启 DSH；`src/plugins/agent_chat/config.py` 保存代码默认值，`.env.agent_chat.example` 提供模板，实际私有配置会覆盖默认值。`AGENT_CHAT_POKE_ENABLED` 控制机器人是否能向外戳人，与这里的接收回应开关分别生效。`ai 状态` 显示当前概率和冷却。

### 连续 @、等待反馈与延迟

同群连续直接提问合并为一批，保留每个人的消息、身份和附件引用，并明确告诉模型本轮需要回答哪些消息 ID；可以分别称呼群友、合答相近问题。生成期间新来的 @ 留到下一批，不覆盖前面的请求，普通随机接话不能挤掉直接提问。每条提问独立计算600秒等待预算，旧问题过期不会连带丢掉刚来的新问题。队列在内存中，意外退出不自动重放；发布时应等现有任务空闲。

默认一批最多8条，超过上限或全局待处理群数已满会提示未排上；默认在后台静默等待，不发送“排队或处理中”提示。需要时管理员可用 `AGENT_CHAT_NOTICE_AFTER` 选择等待提示秒数，0 表示关闭。额度用完、过期、暂停和失败也给明确提示。同群同类提示30秒内最多一次，不调用模型、不计模型额度；QQ 本身断线时无法保证提示送达，提示发送失败不重试也不暂停模型会话。`ai 状态` 显示当前群待处理问题数和是否存在任务。

安全恢复只适用于已知连接中断/超时：失败回合不会重新请求模型；确认取消完成、最后回合结束、队列空、输入来自桥接、预设一致且没有发送不确定后，保留原会话继续后面的新提问。未通过校验、模型/协议异常、人工插入的会话输入和 QQ 发送不确定，仍须人工处理。

速度由本地合并/冷却、并发排队、历史长度、服务商首个输出等待、模型生成和工具调用共同决定。2026-10-26 独立新会话抽测：当前模型普通聊天三次基线约3.1～5.6秒，显式请求关闭思考后约3.0～4.8秒，AnySearch一轮约10秒；样本很少，不代表长会话或高峰时延保证，不能断言深度思考是唯一原因。当前部署保留 `chaoschild / deepseek-v4.1-flash`，只为该模型补全 DSH 思考能力声明与 DeepSeek 请求格式，并选用 `off`；不更换 API Key。

该思考设置属于本机 DSH profile，不是人设里的“不许思考”。换服务商或模型时必须重新验证，不能把 DeepSeek 的兼容参数套给其他模型。DSH 当前的 `session/selectModel` 同时保存默认选择；本次只在原模型上选择 `off`，会影响以后沿用该默认选择的新会话。若想恢复思考，可在 DSH 为该模型选回所需档位，或从私有部署备份恢复原模型配置。已运行的群会话应逐个确认实际选择，保存人设文件不会改变档位。

### 当前部署节奏与仓库默认值

日常修改项目根目录的 `.env.agent_chat`（本机 `E:\rerika\ErikaBot\.env.agent_chat`）；每个已有选项上方已添加中文说明。`.env.agent_chat.example` 是公开安装模板，`src/plugins/agent_chat/config.py` 定义默认值和可配置范围，日常无需改Python代码。

| 常用设置 | 当前私有值 | 范围与作用域 |
| --- | --- | --- |
| `AGENT_CHAT_MAX_CALLS_PER_HOUR` | `90` | 1–300；每群滚动60分钟的对话额度 |
| `AGENT_CHAT_SEARCH_MAX_PER_HOUR` | `6` | 1–30；每群滚动60分钟的联网回合，同时占对话额度 |
| `AGENT_CHAT_LEARNING_MAX_PER_HOUR` | `12` | 1–60；所有群共用的后台记忆/黑话学习额度 |
| `AGENT_CHAT_PROACTIVE_DAILY_LIMIT` | `6` | 1–24；每群每天的闲时主动尝试，同时占对话额度 |
| `AGENT_CHAT_COOLDOWN` | `2` | 秒；同群相邻回合最小启动间隔 |
| `AGENT_CHAT_QUEUE_TIMEOUT` | `600` | 秒；每条已接受提问的最大排队等待 |
| `AGENT_CHAT_TIMEOUT` | `300` | 秒；开始调用DSH后的单轮超时 |
| `AGENT_CHAT_MAX_CONCURRENT` | `2` | 所有群共享并发，允许1–8；未写入文件时采用代码默认值 |
| `AGENT_CHAT_AMBIENT_PROBABILITY` | `0.02` | 随机接话2%，允许0–0.2 |
| `AGENT_CHAT_OBSERVATION_SECONDS` | `60` | 秒；发送后观察时间，允许30–900 |

修改前保留私有备份；修改保存后等待现有任务完成，再停止原NoneBot进程，并在项目目录执行 `poetry run nb run`。不要在旧进程仍占用8080端口时重复启动。只改本文件不需要重启DSH、重置会话或清空数据库。用超级用户命令 `ai 状态` 核对生效值；滚动额度和历史用量在重启后保留，例如原来已用60轮，提升到90后可继续用剩余30轮。若文件值未生效，检查是否存在同名进程环境变量覆盖。


当前私有配置每群滚动60分钟最多90个对话回合，排队等待上限600秒，单轮DSH执行超时300秒。随机接话2%，发送后观察60秒、最多3次续聊判断；群内安静15分钟后可主动发言，每群每天最多6次主动尝试。北京时间23:00–09:00仅停止闲时主动发言，随机接话、直接@和引用仍按各自规则处理。主白名单由私有配置维护，当前6个群各自保存会话，共用同一版人设。

仓库示例默认仍关闭插件、读图、自主发言，随机概率为 0，需按实际用途启用。`AGENT_CHAT_PROACTIVE_GROUPS=[]` 表示沿用主白名单；主白名单新增群后重启机器人即可，群会话会按需建立。已有群不会因追加群号而丢失记忆。

| 常用参数 | 默认值 | 用途 |
| --- | --- | --- |
| `AGENT_CHAT_FORWARD_PERSONA` | `true` | 首次完整载入、后续短提醒；关闭只影响对话里的角色投递，不关闭预设校验 |
| `AGENT_CHAT_CONTEXT_MESSAGES` | `20` | 首次或单批新增背景消息上限；已接受的直接提问另行保留 |
| `AGENT_CHAT_DEBOUNCE` / `AGENT_CHAT_COOLDOWN` | `1` / `2` 秒 | 合并同群短时消息并限制调用节奏 |
| `AGENT_CHAT_BATCH_LIMIT` | `8` | 每群一批直接提问上限；接受后保留所有问题，超出的新提问明确提示未排上 |
| `AGENT_CHAT_NOTICE_AFTER` | `0` 秒 | 排队/处理中一次等待提示，0关闭；同群同类提示30秒内最多一次 |
| `AGENT_CHAT_MAX_CALLS_PER_HOUR` | `60` | 每个对话共用的调用额度，包括随机、自主、沉默和失败尝试 |
| `AGENT_CHAT_QUEUE_TIMEOUT` | `600` 秒 | 最新触发入队后的等待上限，包含消息合并、冷却、同群排队和等待并发名额；允许配置 5～3600 秒 |
| `AGENT_CHAT_MAX_CONCURRENT` / `AGENT_CHAT_MAX_PENDING` | `2` / `16` | 模型并发数及正在处理或排队的对话数上限 |
| `AGENT_CHAT_TIMEOUT` / `AGENT_CHAT_MAX_REPLY_CHARS` | `90` 秒 / `600` 字符 | DSH 回合超时和最终可见回复长度 |

各参数完整定义见 [配置模型](../src/plugins/agent_chat/config.py)，建议从 [.env.agent_chat.example](../.env.agent_chat.example) 开始设置。

连续 @ 会合并到最新待处理机会，已有消息仍由增量上下文提供；同群上一轮结束后才开始下一轮。`AGENT_CHAT_QUEUE_TIMEOUT` 从最新触发入队时起，用单调时钟计时，不受系统校时或 QQ 消息时间偏差影响。超过等待上限的机会不再启动模型、不消耗调用额度；这与模型已经运行后的 `AGENT_CHAT_TIMEOUT` 是两段独立预算。网关刚投递时已经超过 120 秒的旧消息仍不会触发回复。

`ai 状态` 会显示最近一小时已用／上限和排队等待上限。修改私有 `.env.agent_chat` 的 `AGENT_CHAT_MAX_CALLS_PER_HOUR=90`、`AGENT_CHAT_QUEUE_TIMEOUT=600` 后重启 NoneBot 即可，无须重启 DSH 或重建群会话；小时额度是滚动窗口，不因重启而清零。

## AI 自主联网搜索（AnySearch）

搜索完全交给 DSH 已安装的 `@anysearch/anysearch-dsh`（本机 0.1.8）。模型在同一个 DSH 回合里自主调用原生 `web_search`，阅读工具结果后再生成最终群聊回复。Python 负责消息桥接、搜索授权、用量记录和输出过滤；搜索请求与结果读取由 DSH 原生工具完成。

在 DSH 的当前 profile 安装并启用 AnySearch，将 `web.searchProvider` 设为 `anysearch`，再安装本项目更新后的安全预设。首次迁移须重启 DSH 与 NoneBot；之后仅改以下开关只需重启 NoneBot：

```dotenv
AGENT_CHAT_SEARCH_ENABLED=true
AGENT_CHAT_SEARCH_AMBIENT=false
AGENT_CHAT_SEARCH_PROACTIVE=false
AGENT_CHAT_SEARCH_MAX_PER_HOUR=6
# 同一原生回合可能包含多段模型推理，当前部署给出 300 秒总预算。
AGENT_CHAT_TIMEOUT=300
```

当前全部 6 个白名单群沿用这组开关。默认只有 @、引用机器人和允许的私聊可以搜索；随机接话与主动发言默认没有搜索授权。是否需要查询由模型判断，普通闲聊不会因为开放能力就必然调用搜索。无需专门搜索命令，例如“帮我搜一下明日堇sumire是谁”。专名应保持完整，资料无关或不足时明确无法确认，不能从空结果推断名字写错或人物不存在。

### 次数、费用与输出

- 每个 DSH 回合最多执行 **2 次 `web_search`**，每次仅 1 个至多 120 字符的公开主题、最多 3 条来源。模型可在第一次结果不足时调整关键词再查；原生工具每次超时 20 秒，整个 DSH 回合仍受 `AGENT_CHAT_TIMEOUT`（代码默认 90 秒，当前部署 300 秒）约束。原生工具会把多段模型推理合并进一个回合，慢模型可能需要增加总预算；这不是取消超时，也不代表通常需要等满 300 秒。
- 每个“机器人账号 + 群/私聊”每小时最多 6 个实际尝试搜索的回合。首次工具调用即记一次，失败和空结果也计数；普通未搜索回合不消耗搜索额度。重启 NoneBot 或 `ai 重置` 不返还额度。每群串行、总并发仍由原有机器人限制控制。
- 每小时 60 次的对话额度统计 **DSH 回合**，不等于模型底层请求次数。一个原生工具回合内可能包含多次模型推理与工具结果阅读，仍会产生 token 费用。人设首次/压缩后投递和群聊增量发送保持不变。
- AnySearch 凭据由 DSH 管理，不写入机器人的配置。未配置时插件可使用匿名访问，但能否成功、配额和收费取决于 AnySearch 当前服务。不要将聊天 API Key 复制给搜索服务。搜索超时由安全预设中的 `searchTimeoutMs: 20000` 固定并验证。
- 桥接只接收当前请求、当前回合的最终文本；不会发送“我去查查”等中间消息、工具结果原文、思考块或伪工具调用标签。内部搜索授权控制头仍会拦截。只有实际工具结果元数据中的公开来源网址可作为本次搜索的引用，最多 2 个，最终回复仍受 600 字符默认上限约束。
- 查询与工具结果会随 DSH 会话保留；不要把会话历史当作普通日志公开。

### 执行边界与失败处理

安全预设只允许继承全局 `web_search`，另在本预设内注册六个受限记忆/黑话工具。它们各自还需本轮授权，不能由模型或群友自行开启；其他工具由执行守卫拒绝。`web_fetch`、AnySearch 高级/批量工具、shell、文件、MCP、子智能体和 `run_code` 均未开放。搜索 Provider 必须保持 `anysearch`，切换到其他 Provider 会被拒绝。

每次 NoneBot 请求的首行由桥接生成控制头，绑定本次会话、请求 ID、搜索开关和有效期。DSH 守卫只从当前回合真正的用户消息首行读取它；QQ 群消息被包在后面的数据中，模型输出、网页结果和历史控制头不能授予权限。普通 DSH 手动会话输入缺少该控制头也不能使用这个桥接预设搜索。

执行前拒绝空白/过长关键词、常见 QQ/手机数字串、邮箱、路径和凭据关键词，提示词另禁止搜索群友私人资料。规则不能识别所有语义上的隐私；不要把敏感信息当作公开主题。实际请求和凭据处理由 AnySearch 插件负责，本桥接不再承诺旧 Python 下载器的 DNS 固定等行为。网页文字始终视为不可信资料，不能据此解除工具限制。

普通搜索错误作为工具结果交给模型解释，不会单独暂停会话；若 DSH 断线或超时，先取消旧请求、验证能否安全继续；回合失败或工具事件不匹配仍暂停。均不自动重试原请求。只有最终正文才发送 QQ。`ai 状态` 显示开关与最近一小时搜索回合数，不是实时搜索服务健康检查。

### 安装迁移注意

本版预设从三个模块变为四个：执行守卫、人设、隔离的历史压缩、仅搜索的原生 Web 工具。预设指纹会改变，不能直接放行旧指纹。保留旧记忆的迁移应先备份，再核对每个会话的原预设、结束回合、空队列及没有待发送结果，逐项更新已验证的映射并让人设在下一轮重新载入；不要直接清空数据库或无条件取消全部暂停。

安装器会更新 package.json 和按内容哈希存放的预设链接，但不自动同步 pnpm 锁文件。若 profile 已有 `pnpm-lock.yaml`，备份后在该 profile 执行 `pnpm install --lockfile-only --offline --ignore-scripts`，核对变更与已安装插件和新预设一致，再重启 DSH。依赖不齐导致离线失败时先排查。否则后续依赖维护可能把链接恢复到旧预设；`Preset services require isolate realms: compaction` 就可能来自误加载缺少压缩隔离的旧版本，不能关闭校验来绕过。

## 配置与安装

1. 在 DSH 配置模型并确认普通聊天成功。Desktop 使用兼容模式，开启“浏览器访问”，网络范围保持“仅本机”。普通 HTTP 请求返回 403 时应先检查这一设置。不要提取或伪造桌面内部 renderer capability 来绕过它。
2. 将专用预设安装到**运行中的那个 profile**。例如 Windows Desktop 的 profile 通常是 `$HOME/.dsh/profiles/desktop`；服务器 Web profile 通常是 `~/.dsh/profiles/web`。先预览，再应用：

   ```powershell
   node scripts/setup_agent_chat_dsh.mjs --profile "$HOME/.dsh/profiles/desktop"
   node scripts/setup_agent_chat_dsh.mjs --profile "$HOME/.dsh/profiles/desktop" --apply
   ```

   安装器保留已有依赖及 bundles，备份 package.json，并将守卫与预设复制到 profile 下按内容哈希命名的目录，再创建模块链接。切换 Git 分支不会改变已部署守卫。不会安装网络依赖、启动进程、删除历史或修改模型配置。应用后重启 DSH；若 profile 管理器要求安装依赖，按该版本 DSH 的插件安装流程操作。

3. 在项目根目录创建私有配置：

   ```powershell
   Copy-Item .env.agent_chat.example .env.agent_chat
   ```

   填写准确的 `AGENT_CHAT_DSH_URL`（Desktop 当前监听端口可能不是 3080）、白名单群号、DSH 登录链接里的 token 或有效的 `dsh-auth-*` Cookie。两种连接凭据选一种。不要把 LLM API Key 当作 DSH 登录 token。不要将凭据写入本仓库已跟踪的 `.env.prod`，也不要粘贴到群内。

   插件自动读取 `.env.agent_chat`；优先级为进程环境变量 > 此私有文件 > NoneBot 配置 > 默认值。私有文件禁止 `${...}` 插值，防止意外改变凭据。`AGENT_CHAT_PROVIDER` / `AGENT_CHAT_MODEL` 同时留空则使用 DSH 默认模型，也可成对填写以固定模型。

   远程服务器通过 SSH 本地转发接入，例如 `ssh -N -L 3080:127.0.0.1:3080 user@server`，插件 URL 仍使用 `http://127.0.0.1:3080`。插件仅允许字面量回环地址，HTTP 和 WebSocket 均拒绝重定向，不向任意域名转发凭据。

4. 检查真实 DSH：

   ```powershell
   poetry run python scripts/check_agent_chat.py
   poetry run python scripts/check_agent_chat.py --smoke
   ```

   第一条只校验认证与实际预设组成；第二条新建独立 DSH 会话，调用模型一次（产生费用），确认请求与回包对应并清理待执行任务。不会给 QQ 发消息，也不会改已有会话。该诊断会话的历史保留在 DSH。

5. 确认通过后设 `AGENT_CHAT_ENABLED=true`，保留明确白名单，然后 `poetry run nb run`。修改配置后重启机器人。默认人设位于 [roles/古户绘梨花.md](../roles/古户绘梨花.md)，安装器会将其作为纯文本嵌入安全预设；也可用 `--role "roles/我的角色.md"` 选择其他文件。修改人设后重新安装并重启 DSH，旧映射会要求 `ai 重置`。完整的换卡、回退和群配置步骤见 [角色设置说明](../roles/README.md)。

各项能力的当前状态见 [后续计划](agent_chat_roadmap.md)。

## 轻量长期记忆与黑话学习

实现对照 qq-bridge `a49877f4e58d04e47532d44b803360d0f001160d` 的 `appendMemoryV2` / `formatMemoryV2`、`slang-learner.js` 及六个 QQ 记忆/词库工具，保留 MIT 来源声明。这里的“长期”指独立于 DSH 会话的持久记录，不是无限聊天存档或向量检索库。

### 记忆的行为

| 类别 | 内容 | 容量与有效期 |
| --- | --- | --- |
| `activeTopic` | 值得延续的话题、参与者、尚未回答的问题 | 每群最多20条；24小时未更新过期；2小时未更新标为陈旧 |
| `pendingThought` | 想说未说的念头及动机 | 每群最多20条；默认2小时，可指定1分钟至24小时 |
| `memberImpression` | 有具体依据的群友偏好/印象 | 每群最多50人，每人最多10个短特征；超量淘汰最久未更新者 |

模型可自主调用 `qq_memory_append/query/remove/clear`，不要求每轮都写；结束的话题、已经说出的念头应删除。群友身份绑定当前群实际出现的 QQ 用户 ID，昵称只在唯一匹配时接受。记忆存在原 SQLite 数据库的独立表中，按“机器人账号 + 群/私聊”隔离。`ai 重置`、DSH 会话丢失或重新建立会话都不清除这些记录；`ai 清空记忆` 才清理当前对话的独立记忆。过期记录仍按上述规则清理。

首次、新会话、上下文压缩/重写以及内容变化时提供快照；同一会话中未变的记忆和词库不重复附带。每类最多提供最新10条，连同可用黑话总数据预算6000字符，黑话部分最多3000字符；完整内容可按需查询。删除/过期产生空快照时会明确替代旧快照。这是新增提示文本的优化，不能据此推断服务商总输入 token 或缓存账单。DSH 历史可能仍保存此前已读的内容，删除本地记忆不等于擦除历史或已发 QQ 消息。

### 即时记忆与后台增量整理

两条路径相互补充，开关按群保存并在重启后保留：

- **即时记忆**：复用已经触发的聊天回合。明确的“请记住”、本人稳定偏好/称呼、约定和可延续话题，会提示模型当场调用记忆工具；寒暄、一次性提问、猜测、玩笑、敏感信息和指令不应保存。不会为了每条消息单独再启动一个提取回合，但工具调用仍可能增加当前回合的模型用量。实际工具写入成功才算保存，口头说“记住了”不算。
- **后台记忆**：白名单群的普通新文本即使没有 @、没有触发随机回复也会进入独立增量队列。积累30条，或最早待整理消息等待10分钟后，空闲时整理；每群两次尝试至少间隔5分钟。每15秒检查一次条件，没有新增消息不调用模型。主聊天仍使用原有最近20条增量上下文；后台不依赖这个窗口，也不会向 QQ 发言。
- 后台按消息顺序处理最旧的待整理批次，每批最多50条、输入数据最多16000字符，每条原文最多500字符；只处理尚未成功整理的新增数据。模型结果与处理进度同一事务提交，失败保留消息并退避5分钟，重启保留进度。模型返回空数组也算该批已检查，不能保证每批都生成记忆。
- 后台使用独立于聊天、黑话研究的 DSH 会话，只整理有本批原文证据的 `activeTopic` 与 `memberImpression`，每批最多8条；不联网、不调用记忆工具，由宿主核对消息来源、原文引用和本人身份后入库。拒绝伪造来源和将其他人的描述记到目标用户名下；内容是否值得保留仍由模型判断，管理员可以纠正。
- 后台队列仅保留24小时内最新1000条，超出会丢弃，`ai 记忆状态` 显示累计丢弃数。只处理开启后新收到的消息，不倒灌历史；命令、私聊、机器人自己的消息、引用/合并转发和图片/音频正文不进入此队列。它不是完整聊天存档。
- 记忆整理与黑话提取/研究共用 `AGENT_CHAT_LEARNING_MAX_PER_HOUR`（默认全局12轮/小时），轮流获得机会，只在没有聊天任务运行或排队时启动，受原有并发限制。失败也占额度，不以其他会话绕过预算。DSH 自己维护后台会话历史，增量输入不代表账单只计算新消息。

配置默认值：`AGENT_CHAT_MEMORY_IMMEDIATE_ENABLED=true`、`AGENT_CHAT_MEMORY_BACKGROUND_ENABLED=false`；两者都受部署能力开关 `AGENT_CHAT_MEMORY_ENABLED` 限制。阈值对应 `AGENT_CHAT_MEMORY_BATCH_THRESHOLD=30`、`AGENT_CHAT_MEMORY_INTERVAL=600`、`AGENT_CHAT_MEMORY_MIN_INTERVAL=300`（后两项为秒）。本机本次部署为全部现有白名单群开启即时和后台记忆，之后新增群沿用配置默认值；命令设置优先于这些默认值。

关闭即时记忆只禁止聊天回合写入/删除，仍可读取已有记忆，后台可独立工作。关闭后台或总开关会停止后台收集并清空待整理队列，尚在执行的旧整理结果不会写回；已经发出的模型请求可能仍产生用量。总开关关闭后也停止聊天端记忆读取/写入，但不删除已保存数据，管理员仍可查看。重新开启只从新消息继续。`ai 忘记` / `ai 清空记忆` 同时使此前积压与在途整理失效，避免旧消息重新生成刚删除的记忆；DSH 历史中曾经看到的内容无法因此抹除。

### 后台工作会话复用

即时记忆直接使用当前聊天回合；后台整理按“机器人账号＋群号＋任务类别”持久绑定工作会话：每群一个记忆工作会话、一个黑话工作会话，黑话提取与研究共用后者。它们和正常聊天会话分开，六个群正常最多需要12个后台工作会话。绑定继续保存在 `memory_learning_state` 与 `knowledge_learning_state`，重启不会因为任务中断丢弃绑定；现有消息游标、失败预算和待处理数据不清空。

每次复用都先读取DSH的真实预设、队列和最近回合，确认队列为空、旧回合已结束且输入属于桥接。离线、任务仍运行、人工插入内容或校验失败时保留原绑定并退避，不以不断新建会话绕过故障。模型已经完成但输出JSON无效时，保留同一工作会话，不取消已结束的回合；生成超时/中断时仅清理本次确实开始的任务，下次仍须重新检查。失败仍计入每小时预算；修复不会自动重复QQ发送。

首次没有绑定、DSH明确返回会话不存在，或固定预设/显式模型配置指纹改变时才新建。配置改变先确认旧工作会话空闲，再通过原生 `workspace/archiveSession` 归档旧会话，确认成功后替换；归档仅隐藏列表，不删除日志。归档或校验失败时不新建替代会话。旧版本已失去绑定的历史会话不会仅凭标题被自动接管或批量归档。

本轮提取与研究提示明确只使用当前批次证据，继续核对真实来源与版本；复用不会放松跨群隔离或人工锁定。DSH仍维护工作会话历史，复用并不等于后续调用只计算新增token，后台压缩策略保持原样。

### 查看记忆：合并转发与易读排版

`ai 记忆` 将当前对话的有效记忆整理成一份合并转发，分为“最近在聊的事”“想接着聊的事”“对群友的印象”，每条之间空行分隔；群友印象显示昵称和内容，默认不显示数据库编号或英文类型标签。每类较新的内容在前。`ai 记忆 话题`、`ai 记忆 想法`、`ai 记忆 群友` 可筛选，原有英文分类参数仍兼容。

长列表每页最多10个节点、每节点最多1800字符；不再把全部记忆截断到3500字符。只发送当前页，在卡片内提示下一页命令，例如 `ai 记忆 2` 或 `ai 记忆 群友 2`。内容用 NoneBot 原生文字段编码，预览只含固定说明和条数，沿用黑话报告已验证的短预览合并转发方式。失败只给一条提示，不自动重发或展开刷屏。

需要删除单条时，用 `ai 记忆 管理` 或 `ai 记忆 群友 管理` 临时显示删除编号，再用 `ai 忘记 编号`；默认阅读视图仍隐藏编号。仅超级用户可查看当前已开放群/私聊的记忆，不提供跨群导出。没有有效记忆时仍给简短说明。展示不调用 LLM、不改写记忆内容或数据库结构；原有过期清理照常执行。

当前保留策略：话题最后写入后24小时过期、最多20条；待聊想法默认2小时（工具可设1分钟–24小时）、最多20条；群友印象没有时间过期，同一群友聚合为一条，每人最多10个短特征、每群最多50人，容量满时淘汰最久未更新项。话题仅同正文合并，特征仅精确去重，尚没有定期语义归并、冲突消解或旧事件提炼。

模型快照每类最多选最新10条，记忆与黑话数据总预算6000字符、其中黑话最多3000字符；首轮、内容变化或历史压缩后才重新附加。字符预算不是 token 预算，旧快照在 DSH 历史中仍可能计入输入，直到历史压缩/裁剪。因此容量有界并不等于没有重复语义或历史开销。后续优化可先增加同义合并与冲突更新，再按当前成员/话题选取相关记忆；这次展示更新未实现这些语义整理策略。

### 黑话/梗的学习流程

1. 只收集白名单群新到达的本人纯文本，不收录私聊、机器人自己的消息、显式命令、引用/合并转发正文或图片/音频内容。即使没有 @ 或随机接话没命中，普通文本也可以进入学习窗口；`their_ana` 的被动语录回复不阻止学习。
2. 每群积累至少10条新消息，距离上次整理至少5分钟，从最多80条、每条200字符的窗口提取和修订词义。直接对话中也可用 `qq_slang_submit` 及时保存，不必等后台批次。原词必须在实际输入中出现；模型提供原消息编号和逐字引用，宿主核对。明确解释需解释性语句；从用法归纳需至少两条不同消息。模型仍可能误解语义，这不是事实正确性的保证。
3. 有依据的解释保存为“自动”并立即可供聊天查询/快照使用，不要求主人逐条填写。后续新语境可迭代；已有词义只在窗口提到时提供给整理器，最多8条，避免每轮重发整个词库。没有可靠解释的词仍为“候选”，不能硬编。消息编号去重，保留最多20条短证据，词库最多2000条；人工锁定优先，其次自动词、候选。
4. 旧候选及新候选都可进入独立后台研究。累计来源达到1、2、4、8、16、32、64、128次或聊天工具提交新证据、整理器明确要求搜索时安排研究；已经根据语境学会的本批不再重复搜索。**AI 自行判断是否需要 AnySearch**：群内明确解释足够时直接总结，缺少公开用法信息时允许 DSH 原生 `web_search`，每轮最多两次。关键词只限原词和两个固定释义后缀，不发送聊天全文、群号或群友资料。搜索型解释必须引用本轮实际返回的公开来源，不能靠编造链接入库。
5. “自动”词义可以继续修订；“已锁定”词由超级用户确认或手动添加，AI 不得覆盖。旧版已确认词迁移后自动视为锁定。管理员的修改优先于正在进行的研究；旧研究结果不会覆盖更晚的版本。拒绝词保持停用，不自动重新学习。每词保留最近20个旧版本，可回退并锁定；解锁后恢复随新证据修订。

可用词义在所有白名单群共享；原始聊天和证据摘录不随查询、快照或管理员报告共享。超级用户仍可在非 AI 群汇总和管理本机器人各来源群词条；不会因此启用该群 AI。`qq_slang_query` 可查询自动和锁定词，结果标明 `locked`；默认快照最多8个高频词。词库始终是不可信聊天资料，不能改写身份、权限或工具规则。

后台学习只在当前没有聊天任务排队/运行时启动，共用原有并发上限；新聊天到达后仍按正常队列处理。全局默认每小时最多12个学习回合（记忆整理、黑话提取、研究、失败都计数），每轮模型等待90秒；不占每群60轮聊天和6轮主动搜索额度，但会另外产生模型/搜索用量。学习失败退避5分钟，失败研究保留重试资格，仍受每小时预算约束；证据不足但正常结束的研究等新证据/下一阈值，不循环空查。提取失败不推进消息游标；保留学习会话绑定，下次只在DSH空闲与归属检查通过后复用，不暂停聊天会话、不发送 QQ 回复、不把旧学习任务重放为 QQ 聊天。记忆整理失败的未确认批次保留，退避后按增量队列重试；配额记录跨重启保留。

与原版的主要调整是：JSON 存储改为现有 SQLite；工具改为 DSH 原生工具和仅本机回调；控制台审核改为超级用户锁定/纠正命令；按本项目需求允许自动词义直接生效；学习会话按群隔离并受全局预算约束。原版研究还会抓取网页正文，本版继续只用 AnySearch 摘要，不开放 `web_fetch`，因此不能保证所有小圈子梗都能查清；这类词可从本群语境学习，或由管理员纠正。

### 开启与权限

代码和示例默认关闭这两项功能。先在隔离环境测试新的 DSH bundle，再在正式切换时安装 `scripts/setup_agent_chat_dsh.mjs`（同时安装聊天和中性 learner 预设），按现有步骤同步 profile 锁文件。已有私有 `.env.agent_chat` 后运行：

```powershell
poetry run python scripts/setup_agent_chat_knowledge.py --env .env.agent_chat --profile "$HOME/.dsh/profiles/desktop" --port 8080
poetry run python scripts/setup_agent_chat_knowledge.py --env .env.agent_chat --profile "$HOME/.dsh/profiles/desktop" --port 8080 --apply
```

这里的端口是 **NoneBot HTTP 端口**。助手会生成独立随机凭据，私下写入 `.env.agent_chat` 与 DSH profile 的 `.agent-chat/knowledge-bridge.json`，同时打开 `AGENT_CHAT_MEMORY_ENABLED`、`AGENT_CHAT_SLANG_ENABLED`。不打印凭据；Windows 文件权限限制为当前用户和 SYSTEM，其他系统使用600权限；保留私有配置备份。不改模型 Key，不重启进程。首次部署还需在验证通过后重启 DSH 和 NoneBot，并校验迁移原群绑定，保留原会话 ID、暂停状态及历史。

这版默认 DSH 和 NoneBot 同机。DSH 调用固定 `127.0.0.1` 地址，NoneBot 同时校验来访地址、独立凭据、当前服务器持有的会话/请求租约、工具权限和调用 ID；模型不能指定群号、URL、路径或令牌。每轮最多6次记忆/词库工具调用，同一个调用 ID 重复送达不会重复写入；失效、手动或其他会话的请求被拒绝。没有通用文件、代码执行或任意 HTTP 工具。跨服务器部署需要另外配置受控反向隧道和私有凭据，不能将该端点直接暴露公网。

`AGENT_CHAT_LEARNING_MAX_PER_HOUR=12` 控制全局学习预算。修改环境配置后重启 NoneBot；使用下列记忆命令则立即生效、不需重启、不调用模型。关闭功能不删除已存记忆。AnySearch 研究开关随黑话学习开启，独立于群聊的 `AGENT_CHAT_SEARCH_ENABLED`；普通随机回复的搜索授权保持原规则。

## 人设的实际投递

默认 `AGENT_CHAT_FORWARD_PERSONA=true`：DSH 系统预设保留完整角色卡；桥接在每个会话首次使用时，另外将同一次已校验预设中的完整角色提示送入对话。后续普通轮次只发送短提醒和新增群聊 JSON，不再逐轮追加完整卡片或重复最近 20 条消息。@、随机接话、自主发言和图片问答共用这条路径。不会从群消息、昵称或本地尚未安装的角色文件拼接管理员人设，不转发凭据或插件配置。

人设载入状态与消息进度按群持久化，机器人重启后继续使用。检查 DSH 的持久事件发现历史压缩或重写、无法确认历史连续性时，会保守补发完整人设；发生在当前生成期间的压缩会在下一次请求检查并补发。只有 DSH 明确完成的请求才推进进度，模型选择 `[SILENT]` 也算已读取。网络故障不盲目重试；只在清理和会话校验通过后恢复后续输入。新建、明确丢失后重建或重置的会话会重新初始化；从旧版升级首次运行会补发一次，并保留原会话及记忆。

这是减少重复累积，**不代表后续 API 请求不再计算人设或历史 token**：DSH 仍向模型提供系统提示与会话上下文，缓存是否命中及实际计费取决于模型服务。图片按下方“读图”的关联选择、跨轮去重和原生历史省略规则处理；明确追问仍可重新附带原图。

三个连续测试回合向 DSH 新增的文本分别约为 **9830、542、544 个字符**：第一次包含完整角色，之后只带短提醒与新消息。该抽查同时验证了人物别名和重建 Python 客户端后的记忆。字符量随聊天内容变化；生产中的历史会继续由 DSH 压缩，并不等同于永久、逐字无损的长期记忆。

### 固定规则与长历史开销（2026-10-26）

固定的聊天协议、搜索说明、QQ_REPLY 表达格式和即时记忆规则改为首次注入；后续只带新增消息、待答 ID、日期、本轮联网/记忆状态及 `QQ_ALLOWED` 可操作目标。协议内容哈希保存在 SQLite 的 `prompt_seeds` 表，和群、DSH 会话绑定；重启沿用，规则升级、恢复、重建、压缩/重写后重新补齐。只有完整成功的 DSH 回合才提交标记，失败不会误记为已注入。角色卡和记忆快照仍按各自的版本/变化机制提供。

模型端 JSON 移除内部群键、重复 directed 标志、空引用字段、缩进空格，并将时间戳取整；保留消息 ID、发言者 QQ 号、昵称、正文及非空引用关系。本地原始消息不变，图片、转发、引用/互动的同群时效校验和多人的待答问题保留逻辑继续使用完整记录。字段减少不会放宽执行守卫或发送权限。

同一组合成输入的离线字符对照（后续轮次、联网和即时记忆可用、无新增记忆快照/附件）：1 条消息由 **2069 → 331 字符（减少 84.0%）**，20 条由 **6173 → 2288（减少 62.9%）**。首次/补种轮次仍包含完整规则和必要人设；实际输入随附件、记忆更新、人数变化。该数字不是模型总输入 token、缓存费或端到端速度对照，没有比较 API。

聊天安全预设使用 DSH 原生 `dsh-compaction-basic` 提前摘要：`thresholdRatio=0.25`、`headroomTokens=8192`、`retainTokens=8192`、`maxTokens=4096`、`compactionRetries=0`。以适配器声明 262144 上下文、32768 输出预留为例，原默认触发点为 163840，现为 **65536 个估算 token**。实际阈值取窗口的 25% 与扣除输出预留/8192 余量后的较小值，并非硬性 64K 上限。换用小窗口模型时应重新核对保留预算必须小于阈值，不能只照搬这个例子。

原生摘要保留系统头和至少约 8192 token 的近期完整消息，选区不拆开工具调用/结果；较早内容转为摘要，完整历史仍在 DSH 会话日志。摘要最多输出 4096 token（含提供方计入的思考），单次压力处理不额外重复摘要，原生溢出恢复保留。当前待答问题、最近对话在尾部；人设、记忆快照和协议在检测到压缩后的下一轮补齐。摘要会额外调用当前模型，发生整理的那一轮可能更慢，且不是逐字无损记忆。API 失败时 DSH 保留原历史并继续尝试当前回合，正常回合本身的失败仍走桥接既有暂停/恢复机制。

同一隔离压缩作用域安装了 DSH 原生 `/compact` 人工维护命令，供管理员在 DSH 界面使用；QQ 的 `/compact` 仍是普通聊天文本，不会转发为管理命令，也没有把维护能力开放成模型工具。后台记忆提取会话的压缩策略保持原样。更新该预设需要安装、重启 DSH 并按前述校验流程迁移现有会话的预设指纹，不能靠跳过指纹校验部署。

完成一轮生成后只推进该轮开始时截取的消息边界，生成期间新到的消息留给后续轮次。发送到 QQ 失败时不自动重发；增量记录保留在本地 `delivery` 表，按群与 DSH 会话绑定。自动压缩的内部检查点经过关联验证后处理，避免被误判为外来对话而暂停；真正的并发外来输入仍会暂停。

2026-10-25 的真实抽查发现，当前模型只用系统预设时未稳定遵循人设，所以保留首次对话载入与短提醒。换用能稳定遵循系统人设的模型后，可将该选项设为 `false`，仍保留预设校验、增量聊天与执行端工具守卫。原 qq-bridge 也不是所有路径逐轮注入：v1 的活跃批处理可只发新增消息；v2 可以通过工具读取完整卡片。本桥接不会为省 token 开放角色文件读取工具；搜索使用独立的最小权限规则。

换卡仍需安装并重启 DSH、重置旧群映射，详见 [角色说明](../roles/README.md)。群会话各自独立；更新所有群时先备份本地 SQLite，再停止旧会话、使用同一版预设建立新映射，旧 DSH 历史保留。角色剧情中的“主人”和姓名别名不授予任何管理权限。

## 读图

设置 `AGENT_CHAT_IMAGES_ENABLED=true` 并重启机器人。支持当前提问附图、引用图片和明确看图追问；查找窗口为最近 10 分钟，每次最多 2 张。普通文字聊天不再自动附带最近 20 条里的旧图；随机接话只考虑本次新增消息中的图片。仍遵守 @、引用回复、随机概率、其他插件优先级和调用限流，不会见图就调用模型。

DSH 模型必须实际支持视觉输入。自定义模型未声明输入类型时，DSH 会默认为纯文本；在对应模型条目添加 `input: [text, image]` 后重启 DSH。这个声明不会让纯文本模型获得视觉能力，须实际验证：

```powershell
poetry run python -B tests/agent_chat_image_probe.py --confirm-model-call
```

脚本用不含用户信息的几何图调用模型一次，不发送 QQ 消息。本机 `steinsgate / deepseek-v4-flash` 补充输入声明后已正确识别形状和颜色，没有更换 API Key 或默认模型。

仅从允许对话的结构化 `image` 消息段取图，文本中的任意链接不会被抓取。下载只允许 QQ 图片 CDN：`qpic.cn` 及子域、`multimedia.nt.qq.com`、`multimedia.nt.qq.com.cn`、`gxh.vip.qq.com`。全部 DNS 地址须为公网；固定已校验地址进行连接，保留原主机 TLS 校验，拒绝重定向，不转发 DSH 凭据。图片 URL 的临时授权参数不会写入模型提示或 HTTP 日志。

默认单图输入上限 8 MB、2000 万像素；校验 PNG/JPEG/WebP/GIF 后转成最大边 1536 像素、最多 1 MB 的 JPEG，并去掉元数据。动态图只取首帧。模型服务会收到处理后的图片；Base64 不会作为普通文字发给模型，原始下载字节不单独落盘，DSH 会按自身机制保存附件。

图片有两层去重：QQ 内容标识避免重复下载，规范化图片的 SHA-256 避免不同引用指向同一像素。按群和 DSH 会话记录成功读取；模型失败或不支持图片时不标记已读。显式引用图片、再看/认图等追问会允许重读，优先复用内存中的已处理图片。普通文件名可能复用，不能当作全局内容标识。

默认内存缓存 600 秒、总计 32 MB、最多 64 张；`AGENT_CHAT_IMAGE_CACHE_TTL` 或 `AGENT_CHAT_IMAGE_CACHE_BYTES` 设为 0 可关闭缓存。缓存按对话隔离，重启清空。已读凭据和可选的短描述存入 `data/agent_chat/state.sqlite3` 的 `image_reads` 表（24 小时、每群最多 256 条）；新会话/重置/恢复清空旧凭据，不保存图片字节或签名 URL。已有 DSH 附件仍按 DSH 自身机制留存。

识图同一轮可以附带私有 `image_notes`（每图最多 200 字），不额外调用模型，不发送到 QQ；没有描述时使用该轮可见回答的短摘录。描述是可能不完整、可能出错的历史参考，不能替代原图细节，也不会成为工具授权。

**DSH 原生图片省略也已接入。** 此版本 DSH 自带 `@deepseek-ai/dsh-compaction-image-offload`，不重复安装到会话预设。聊天守卫的 `imageHistory: omit-previous` 在新一轮模型执行前，仅选取该桥接先前轮次的图片，提交原生 `image/offload` 事件，由 DSH 转为省略占位。当前轮图片在搜索等后续工具步骤中继续保留；原附件与会话记录不删除，后续明确追问可重新附图。后台学习预设不启用此策略；未发现原生省略能力时新预设拒绝启动。升级需一起安装 DSH 插件包并更新现有绑定的预设指纹，不能只替换 Python 文件。

这减少重复下载、图像转换和后续请求的旧图像素；不保证固定比例的提速或费用下降，实际还取决于模型响应、服务端缓存和搜索步骤。日志只记录候选/附图/缓存命中/已读跳过数量及准备耗时，不记录图片正文与签名 URL。

URL 获取失败时，可通过安全缓存标识调用 [OneBot get_image](https://github.com/botuniverse/onebot-11/blob/master/api/public.md#get_image-获取图片)。默认不读取本地路径；只有网关返回本地缓存且没有 URL/Base64 时，才需要将具体图片缓存目录填入 `AGENT_CHAT_IMAGE_CACHE_ROOTS`，不要填写整块硬盘或用户目录。

下载或校验失败会明确标记“未取得图片”。DSH 若明确在接纳请求前拒绝图片，可改发一次纯文本说明；不会将断线、超时等不确定错误当作可重试条件。语音尚未接入，不能理解语音内容或音色。

## 随机接话与自主发言

用户选定的活跃配置如下，仓库示例默认仍保持关闭：

```dotenv
AGENT_CHAT_AMBIENT_PROBABILITY=0.05
AGENT_CHAT_PROACTIVE_ENABLED=true
AGENT_CHAT_PROACTIVE_GROUPS=[]
AGENT_CHAT_PROACTIVE_IDLE=900
AGENT_CHAT_PROACTIVE_DAILY_LIMIT=6
AGENT_CHAT_QUIET_START=0
AGENT_CHAT_QUIET_END=0
AGENT_CHAT_UTC_OFFSET_HOURS=8
```

- 普通消息当前有 5% 的调度概率；被已有命令或语录回复占用时不接话，@ 和引用机器人无需抽签。随机消息不会覆盖排队中的 @ 请求，概率不保证固定条数内必回。
- 每 30 秒检查已连接机器人的白名单群。最近 6 小时内有新群消息，且距最后群消息和 AI 发言均已安静 15 分钟，才有一次主动发言机会。启动后至少等待 60 秒；私聊不主动开口。
- 一次机会最多一句，模型可以沉默。一轮安静期间只尝试一次，没有新群友消息就不继续；新群消息到来后重新计时。生成过程中有新消息，旧的主动回复会被丢弃。
- 每群每天最多 6 次主动尝试，沉默和失败也占一次，避免模型反复空转。次数与等待回应状态存入 SQLite，重启和 `ai 重置`不会清空当天额度。
- 当前起止小时均设为 0，全天不设安静时段。仓库默认仍为 23:00—次日 09:00；需要夜间静默时可恢复该配置。@、引用回复始终不受夜间时段限制。
- 共用原有每小时调用上限、冷却与并发限制。`AGENT_CHAT_PROACTIVE_GROUPS=[]` 沿用主群白名单；填写群号可缩小范围，不能超出主白名单。

修改后重启机器人。`ai 状态` 显示读图、随机概率、自主发言及当日次数。分别设置 `AGENT_CHAT_PROACTIVE_ENABLED=false`、`AGENT_CHAT_AMBIENT_PROBABILITY=0` 可关闭主动发言和随机接话。

## 思考标签过滤

独立思考块继续忽略；正文里的 `<think>`、`<thinking>`、`<analysis>`、`<reasoning>` 连同包裹内容，在 QQ 发送前移除，再截断长度。只有结束标签时，之前的可疑内容也丢弃；未闭合的思考段不发送。支持大小写、嵌套和 HTML 转义标签。过滤后没有正文时，直接提问收到固定失败提示，随机/主动发言保持沉默；模型明确的 `[SILENT]` 仍不发言。这是对已识别结构的防护，不声称能判断任意无标记文字的用途。

## 安全边界

`dsh/agent-chat/guard.mjs` 在 DSH 执行端注册单调拒绝守卫，并在 agent 创建时设置只含 `web_search` 与六个已注册记忆/黑话工具的继承白名单。六个本地记忆/黑话工具由独立的本轮授权、当前会话租约和群作用域校验限制。搜索还必须通过本轮授权、公开参数及次数校验；shell、文件、MCP、子智能体、插件安装和未来未知工具均被拒绝。守卫 API 不支持、Provider 不匹配或作用域不正确时直接失败，不降级到普通智能体。

桥接每次请求读取**实际**预设组成，固定要求守卫、人设、隔离的上下文压缩和受限原生 Web 搜索这四项。人设关闭可选运行环境上下文，不接受模板表达式。群聊内容封装为 JSON 数据，斜杠命令不会成为 DSH 控制命令；不转发审批、设置变更或任意 RPC。QQ 消息只创建文本、经校验的引用、个人@和有限QQ自带表情段；可选的贴表情与戳一戳只调用固定的受限Bot接口。模型输出的 `[CQ:...]` 仍作为文字，不会成为图片、@全体或文件操作。

人设使用 DSH 的 `complete: true`，让固定聊天规则和所选角色卡组成完整系统提示，避免继承通用编程助手的身份章节。`includeRuntimeContext: false` 抑制可选运行环境上下文；DSH 的必需上下文仍可能存在，不能将其视为完全隐藏主机元数据的保证。完整提示模式不解除工具守卫。

提示词不能保证模型永不被带偏；这套限制的目标是让带偏的对话无法通过工具操作主机。它依赖可信的 DSH 实现、守卫代码和宿主插件，并非操作系统沙箱。不要给 QQ 专用预设混入未审计插件，不要在桥接管理的 DSH 会话中同时手动聊天或切换预设。服务器部署宜使用独立低权限账号及独立 DSH profile。

连接 Cookie 权限较高，只在本机私有配置中保存。插件不会将它、模型 Key 或服务错误详情发送给模型/QQ；不要开启包含原始协议或请求头的调试日志。允许群的文本与有限图片引用元数据会保存到本地；文本和成功取得的图片可进入 DSH 并发送给所选模型服务。禁用插件后停止记录；既有历史需由管理员按需要清理。

## 运行进程与日志

Windows 上用 `poetry run nb run` 启动后，会出现 Poetry、nb 和 Python 的父子进程。实际提供 NoneBot/OneBot 服务的是监听配置端口的 Python 进程；不能只看任务管理器中任意一个 `python.exe`。PID 会随重启变化，查当前进程可在另一个 PowerShell 窗口运行：

```powershell
$botListener = Get-NetTCPConnection -LocalPort 8080 -State Listen
$botListener | Select-Object LocalAddress, LocalPort, OwningProcess
Get-CimInstance Win32_Process |
  Where-Object { $_.ProcessId -in $botListener.OwningProcess } |
  Select-Object ProcessId, ParentProcessId, Name, ExecutablePath
```

8080 是本部署的 NoneBot 端口，其他部署按实际配置替换。DSH Desktop 是独立进程，界面进程与监听本机 API 端口的子进程可能不同；其窗口关闭是否等于退出，要以端口是否还在监听为准。DSH、NoneBot、NapCat/QQ 不是同一个进程。

本机 2026-10-26 部署使用后台启动并重定向输出，日志目录为用户目录下的 `Documents/Codex/2026-10-24/new-chat/work/agent-chat/interactions-release/`：

- `bot.stdout.log`：标准输出，包含 NoneBot 启动、插件加载和网关连接等日志。
- `bot.stderr.log`：标准错误，可能包含警告和错误；文件为空不代表没有发生过业务问题，应同时检查标准输出和 `ai 状态`。

这些文件是本次启动的日志，不是跨所有历史部署的统一日志目录。旧启动可能写入其他目录；日志更新时间也不能单独作为服务是否存活的依据。当前没有启用 `bot.py` 中注释掉的文件日志处理器，也没有内置日志轮转、自动清理或“一键导出”命令；已经重定向的日志可以直接查看和复制。

查看当前日志末尾（`-Wait` 可选；在独立查看窗口按 Ctrl+C 只结束查看）：

```powershell
$logDir = Join-Path $env:USERPROFILE 'Documents\Codex\2026-10-24\new-chat\work\agent-chat\forward-fix-release'
Get-Content -LiteralPath (Join-Path $logDir 'bot.stdout.log') -Tail 100 -Wait
```

导出已有日志不会断开机器人连接，也不需要重启：

```powershell
$logDir = Join-Path $env:USERPROFILE 'Documents\Codex\2026-10-24\new-chat\work\agent-chat\forward-fix-release'
$exportDir = Join-Path $env:USERPROFILE ('Desktop\ErikaBot-logs-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $exportDir | Out-Null
Copy-Item -LiteralPath (Join-Path $logDir 'bot.stdout.log'), (Join-Path $logDir 'bot.stderr.log') -Destination $exportDir
```

桥接自身只记录固定错误代码，不把模型内容、认证头或远程错误正文写入错误日志；其他插件和框架日志仍可能包含 QQ 号、聊天内容等信息。对外提供前检查并脱敏，不把 `.env.agent_chat`、DSH 凭据文件或会话数据库当作普通日志一并上传。

今后正式启动时可以统一保存到已被 Git 忽略的 `data/agent_chat/logs/`。以下命令只在原机器人已经正常退出、准备正式启动时使用，不要为了收集日志再开第二个机器人：

```powershell
Set-Location 'E:\rerika\ErikaBot'
$logDir = Join-Path (Get-Location).Path 'data\agent_chat\logs'
New-Item -ItemType Directory -Force -Path $logDir | Out-Null
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$stdoutLog = Join-Path $logDir ("bot-$stamp.stdout.log")

poetry run nb run 1>> $stdoutLog 2>> $stderrLog
```

不同启动使用不同文件名以保留旧日志；这仍是输出重定向，不是自动轮转或进程托管。

## 更换 API、Key 或模型

先区分两层连接：**NoneBot → 本机 DSH** 使用 `.env.agent_chat` 的 URL/Cookie；**DSH → 模型服务商** 使用 DSH 中配置的 API 地址、模型和 Key。更换模型 API 不等于更换 DSH 连接凭据。

| 变更位置 | NoneBot 是否需要重启 | 会话与生效注意事项 |
| --- | --- | --- |
| 只在 DSH 更换同一服务商的模型 API Key | 通常不需要 | 等当前回合完成；按 DSH 的保存/加载机制生效，必要时仅重启 DSH。Key 不在本地会话绑定指纹中 |
| 在 DSH 更换模型 API 地址、模型或默认路由 | 通常不需要，仅改 DSH 即可 | 先核对协议、模型能力和上下文上限；不要假定“更改默认模型”会同时切换所有已有群会话，应检查各会话实际选择 |
| 修改 `.env.agent_chat` 中的 DSH Cookie/登录 token | 需要 | 私有配置启动时加载，没有热重载；仅更换认证凭据本身不会改变策略指纹 |
| 修改插件的 `AGENT_CHAT_PROVIDER` / `AGENT_CHAT_MODEL` 或 DSH URL | 需要 | 它们参与会话绑定指纹；重启加载后，旧群映射会暂停并要求管理员处理，不能自动无缝迁移 |
| 更换 DSH profile、机器或全新实例 | 视连接配置变化决定 | 原会话数据与编号可能不存在；先安排数据迁移，不能只复制 Key 就认为历史已迁过去 |
| 修改角色卡、安全预设或守卫 | 按安装流程重启 DSH；部署时安排必要的机器人切换 | 内容变更触发预设指纹变化，旧群映射须核查后重置或迁移 |

插件中 provider/model 留空时由 DSH 决定模型；成对填写时，插件在创建会话时调用 `session/selectModel`。当前没有自动将 DSH 默认模型切换同步到所有既有会话的功能。直接在 DSH 中更换实际模型/服务地址，也不一定触发桥接的配置指纹变化；仍须主动确认实际路由和兼容性。

**更换模型后重新检查读图声明。** 原模型的 `input: [text, image]` 不会自动继承给新模型。若 DSH 返回 `MODEL_DOES_NOT_SUPPORT_IMAGES`，应先用独立测试确认新服务商/模型确实能识别图片，再为这条模型补充 `input: [text, image]`，在正式切换时重载或重启 DSH。不能仅凭模型名称判断视觉能力；声明也不能让纯文本模型凭空支持读图。若 DSH 拒绝图片，桥接会按文字继续对话，只有问题依赖图片时才说明无法看图，不应让聊天中无关的近期图片干扰纯文字问题。

已兼容 Harness 的 `model-selection / notice` 元数据：管理员切换模型时，运行时插入的通知不会再被误认作其他人抢占输入，也不会发到 QQ。真正来自另一个客户端的聊天输入仍会中止当前请求。请在独立会话测试模型，避免同时在桥接使用的群会话里手动聊天。

建议操作顺序：

1. 记录目前 provider、模型、API 地址及 DSH profile，备份需要改的配置，保留回退方法。备份放在不入 Git、访问权限受限的目录。涉及状态迁移时使用 SQLite backup 接口制作一致快照，不在运行中只复制主数据库文件而遗漏 WAL。
2. 在 DSH 新建独立测试会话验证目标 API 的认证、普通文本、人设、历史承接和图片输入。不要在桥接管理的群会话中手动发送测试问题，也不要改群白名单来绕过隔离。
3. 正式切换时尽量等待当前 AI 回合结束，再在 DSH 修改 Key/API/模型。纯 DSH 变更可以保持 NoneBot 与 NapCat/QQ 在线；如 DSH 要求重启，仅重启 DSH，但此期间 AI 暂时不可用，新请求可能失败。当前没有“只暂停 AI、保持其他插件”的运行时维护开关，不能保证热切换期间零失败。
4. 若同时修改 `.env.agent_chat`，保存后在正式应用配置时重启 NoneBot；单纯更新 DSH 模型 Key 不需要因此重启 NoneBot。
5. DSH 恢复后执行 `poetry run python -B scripts/check_agent_chat.py`，检查认证与安全预设。这个命令不调用模型，不能证明模型 Key 正确；需要模型验证时加 `--smoke`，它只新建独立测试会话、产生一次模型调用，不发 QQ 消息。读图还需单独验证视觉能力。
6. 用 `ai 状态` 查看各群是否暂停。未暂停的会话可在新的合格消息到来时继续；已暂停会话不会因为 Key 修好或重启 NoneBot 就自动解锁，按下面的恢复流程处理。AnySearch 搜索不使用聊天 API Key；更换模型后要在独立会话验证其原生函数调用能力，而不只是能否普通聊天。AnySearch 凭据须在 DSH 中单独管理，不能跨服务商直接复用聊天 Key。

只换 Key 不应为了“使它生效”随意执行 `ai 重置`。该命令会清除当前映射与本地输入，后续创建新 DSH 会话；旧 DSH 历史保留，但不会自动合并进新会话。需要保留原有连续记忆的模型切换，应先备份并进行经过检查的会话迁移；当前没有现成的无损批量切换/自动解除暂停命令。

## 保留记忆的恢复、主动引用与合并转发

### `ai 恢复` 与 `ai 重置`

两者只作用于命令所在群或私聊，均仅允许 NoneBot `SUPERUSERS`，群管理员没有额外权限。

- `ai 恢复`：适用于连接故障修好之后的暂停会话。保留原 DSH 会话 ID、历史、本地记录和次数额度；不会调用模型或补发旧消息。下次新消息触发时继续，人设会补充一次。
- 恢复前必须没有本地正在处理的请求；校验当前预设/模型绑定，清理 DSH 队列并取消残留执行，再读取真实会话记录确认最后回合结束、队列为空且最近用户输入来自桥接。检查失败则保持暂停，不能绕过新的安全预设指纹。
- QQ 发送曾超时、或进程退出时停在发送阶段，会持久记录 `delivery_uncertain`，恢复命令拒绝自动放行。先人工确认发送情况；若选择 `ai 重置`，旧发送记录标记为放弃，额度仍保留，不会重发。
- `ai 重置`：清空当前对话的桥接映射和短期上下文，下次建立新 DSH 会话。旧 DSH 历史仍在，但不会自动继承到新会话。
- `ai 状态` 和“当前未暂停”均不是模型服务健康测试。恢复成功只说明会话可继续，不能保证 API 下一次不超时，也不返还使用额度。

### 主动引用、emoji 与 QQ 自带表情

输出格式容错：标准格式仍为 `QQ_REPLY {…}`，同时识别完整的 `<QQ_REPLY>{…}</QQ_REPLY>` 和代码块包装，以及标记后的换行/冒号。只解码完整、唯一的 JSON 对象，不从说明文字中猜测提取，不修补截断 JSON，不执行模型给出的代码或 CQ 字符串。思考内容中的 `QQ_REPLY` 不再误拦截正常最终正文。

`text` 必须是字符串；未使用的动作字段可省略。整数引用 ID 在范围内转为字符串后，仍须匹配当前对话真实消息；动作字段类型错误或出现未知字段时仅保留正文，不执行动作。无效图片笔记只丢弃笔记，不影响正文。发送前再次检查引用目标是否仍在当前对话的10分钟有效范围内，过期则发送正文。完全无法可靠解码的输出仍不给群友显示控制头。

QQ 网络超时或发送确认丢失仍不自动重试，以免重复发言。普通消息发送异常额外记录异常类型、整数错误码和是否带引用，不记录正文、凭据或远端错误原文。`delivery_uncertain` 仍需主人核对；经主人明确批准，可跳过旧回复、保留会话并恢复后续输入，不应直接清空历史。

默认开启 `AGENT_CHAT_REPLY_ENABLED=true` 与 `AGENT_CHAT_FACES_ENABLED=true`。模型可自然直接使用 Unicode emoji；需要引用或 QQ 表情时，由受限输出对象表达选择。引用只接受本轮提供的当前聊天近期真实消息 ID（10 分钟内）；未知 ID、其他群及转发内部节点不能作为引用目标。自主闲置发言不引用旧消息。

当前支持 21 种常见 QQ 自带表情，如微笑、得意、害羞、白眼、偷笑、捂脸、吃瓜等，每条最多两个。也可以只发表情。模型自主决定是否使用，不要求每句都引用或加表情。没有表情图片发送、自动收藏、任意 CQ 解析、@全体、拍一拍或分条发送。

普通正文继续作为纯文本发送；只有校验后的引用与表情字段生成 OneBot 消息段。搜索来源过滤和思考内容过滤仍生效；不合法的内部输出对象不能直接发到 QQ。整个回答仍只发一条，发送结果不确定时不退回纯文本重复发送。

### 自主 @、贴表情和戳一戳

在已开启 AI 的群中，模型现在可以自行决定是否 @ 群友、给某条消息贴表情回应、戳一戳。无需先输入命令；这些选择附在已有的 @/引用提问或随机接话回合中，不会为每条群消息新增模型调用。仅发一个表情回应也可以，不强制再发送一句文字；对实质问题仍提示模型认真回答。收到戳一戳/表情通知不会单独触发模型，避免机器人互戳循环。闲置自主发言不提供旧成员互动目标。

- 正文中的 emoji 沿用普通文本；QQ 表情通过 `MessageSegment.face()`；@ 使用 NoneBot `MessageSegment.at()`。个人@最多两个，不允许@全体，也不会因为每条回复都开启 `at_sender` 而强制@提问者。
- 贴表情通过 `Bot.set_msg_emoji_like()`，每轮至多对一条消息添加一个表情，支持 👍、😂、❤️、捂脸、吃瓜。这是在消息下方回应，区别于把表情发成新消息。
- 戳一戳通过 `Bot.group_poke()`，每轮至多一人。后两项是网关提供的 OneBot 扩展，由 NoneBot 现有动态 Bot API 调度；没有新增 HTTP 客户端、QQ 发包实现或替代连接。
- 目标只来自本轮当前群最近10分钟的真实外层消息和发言者，允许120秒时钟偏差。引用正文、转发内部节点、自称QQ号、其他群成员和机器人自己不能授权互动。发送前再次检查当前记录、白名单、开关和时效。
- 默认每群贴表情间隔30秒、戳人间隔300秒；同一消息24小时内不重复贴表情。尝试记录持久化到原状态库的 `social_actions` 表，重启、`ai 重置` 不清空冷却。每次先登记再调用，超时或失败不重试、不改用另一条接口补发。
- 先发文字，再尝试可选互动；附加动作失败只记录固定错误类型/返回码，不把错误刷到群里，不暂停DSH会话，也不重发文字。只选了动作但动作失败/冷却时保持安静，不谎报成功。

以下配置位于 `.env.agent_chat`，修改后重启机器人即可，DSH无需重启或重置会话：

```dotenv
AGENT_CHAT_MENTIONS_ENABLED=true
AGENT_CHAT_REACTIONS_ENABLED=true
AGENT_CHAT_POKE_ENABLED=true
AGENT_CHAT_REACTION_COOLDOWN=30
AGENT_CHAT_POKE_COOLDOWN=300
```

新增字段仍使用现有 `QQ_REPLY` 受限对象，例如 `{"text":"接住啦🙂","reply_to":"","faces":[],"mentions":["本轮允许的QQ号"],"reaction":{"message_id":"本轮允许的消息ID","emoji":"👍"},"poke":"本轮允许的QQ号"}`。新增三个动作字段可省略，兼容旧的引用/表情格式；未知字段、格式不正确的对象不会作为控制头发到QQ。完全静默 `[SILENT]` 会取消全部动作。人设仍保存在原DSH会话中；这里只更新每轮简短能力说明，没有重新逐轮注入完整角色卡。

实现依据：[NoneBot 消息段工厂](https://onebot.adapters.nonebot.dev/docs/api/v11/message/)、[Bot API 调用](https://onebot.adapters.nonebot.dev/docs/api/v11/bot/)、[表情回应接口](https://napcat.apifox.cn/226659104e0)、[戳一戳接口](https://napcat.apifox.cn/250286923e0)。本项目后续集成同样先查已安装的NoneBot适配器和现有插件，相关约定保存在根目录 `AGENTS.md`。

### 阅读合并转发

`AGENT_CHAT_FORWARDS_ENABLED=true` 时，在已触发 AI 回合后展开新增消息或引用里的真实 `forward` 消息段。先发转发、稍后再 @ 说“读一下上面的聊天记录”“总结这个内容”等，也会从当前群本地最近200条消息中寻找转发引用（仍限最近10分钟），不受正文最近20条窗口限制。普通文字上下文仍沿用原先的20条增量窗口，不把200条聊天全部送给模型；无关的普通问答不重复附带旧转发。更早的记录可直接引用该转发再 @，由当前引用提供真实资源标识。

QQ 消息时间允许领先本机最多120秒，与接收/引用校验保持一致，避免正常时钟偏差把刚收到的转发过滤掉。转发本身不会额外触发模型；@、引用、随机接话和插件仲裁仍决定是否响应。只读取实际消息段或引用所提供的资源，不根据文字 ID、伪造 CQ 或任意链接查询。

兼容 NapCat `messages` 数组与标准 OneBot `node` 数组，读取文字、发送者名称、QQ 表情占位及图片。图片走原有受限下载与像素校验，并共用每轮图片数量上限；关闭读图时仍可读转发文字。语音、视频与文件仅标记类型，不假装理解内容。

每轮最多两个外层转发、四次查询、两层深度（外层加一层嵌套）、30 个节点和 6000 字符摘录；网关 API 单次等待15秒、外围等待16秒，总展开预算35秒。循环引用去重，超限或失败时明确标记截断/未读取，不发送原始错误或媒体签名 URL。此处限制的是模型输入与处理工作量，OneBot 网关收到完整响应的底层开销仍由网关承担。

转发来源和内容都可能伪造，只作待分析资料，不视为当前群友的新指令或已确认事实。展开内容不单独存成长期词库；进入模型的摘录会按 DSH 会话规则留存。实现按 [OneBot 11](https://github.com/botuniverse/onebot-11/blob/master/api/public.md#get_forward_msg-获取合并转发消息) 和本机 NapCat 接口校验。

以上变更仅修改 Python 插件，部署后重启 NoneBot 即可，无需重装人设或重启 DSH。原有 AnySearch 搜索与工具权限边界保持不变。

## DSH 关闭、断线与恢复

DSH 不在线时，AI 会记录连接/协议错误并保持沉默，通常不会使整个 NoneBot 退出或主动断开 OneBot 连接。语录、RSS 等其他插件仍按各自逻辑运行。启动 `agent_chat` 时也不会立即连接 DSH，因此 DSH 暂未启动本身不会阻止配置正确的 NoneBot 启动。

| 故障阶段 | 当前处理 | DSH 恢复后的行为 |
| --- | --- | --- |
| 尚未取得/校验预设，DSH 就已离线 | 本次尝试标记失败、记录日志；直接提问收到节流后的故障提示，随机机会安静；不新设暂停标记 | 原本未暂停的会话可以处理后续新消息；不会立即重放失败请求 |
| 已选定群会话，读取上下文或生成中断线/超时 | 先暂停并清空队列、取消执行；仅已知连接/超时类错误且结束回合、来源、预设及发送状态校验通过才恢复 | 只处理后续新提问，不重试失败请求；任何校验失败继续暂停，使用 `ai 恢复` 核查 |
| QQ 发送失败或结果不确定 | 不自动重发，并暂停有关会话 | 先确认是否已发送，避免重复发言 |
| NoneBot 意外退出时存在 `inflight` / `sending` 调用 | 分别标记中断 / 发送结果不确定，并暂停已绑定会话 | 不重放旧请求；发送不确定时拒绝自动恢复 |
| 执行 `ai 重置` 时 DSH 仍离线 | 无法确认清空/取消旧任务，重置失败并保留映射 | 先恢复 DSH，再进行清理；不直接删除数据库来绕过确认 |

上述“失败前是否已经选定会话”是当前实现中的区别，不能简单理解成“任何错误都永久暂停”或“DSH 恢复就一切自动恢复”。已开始的失败/沉默尝试也计入调用额度；已暂停会话的直接拦截、排队过期和额度提示不增加模型调用次数。恢复后若触及每小时限制，仍需等待额度恢复。

恢复步骤：先重新打开原 DSH profile，确认模型服务与连接凭据有效；运行只读诊断；再由超级用户查询相关群的 `ai 状态`。该命令展示保存的会话状态和功能开关，**不是实时 DSH 健康检查**。如果已暂停，可执行 `ai 恢复`，由程序完成下述核查并保留记忆；如果接受改用新会话，可执行 `ai 重置`。不要无条件修改数据库中的暂停标记。

当前已具备异常隔离、超时、并发/频率限制、暂停持久化、队列清理和不确定结果不重发；它侧重避免重复或错发。若进程恰好在 QQ 发送阶段崩溃，`sending` 状态不会自动补发，但目前也没有发送确认对账，不能据此声称端到端绝不丢消息。尚未实现全局故障熔断、自动健康探测与退避恢复、运行时 AI 维护开关、自动重启 DSH 或日志轮转。DSH 故障不会自动启动另一个不受限智能体作为替代。

2026-10-25 文档核验时，在独立模拟服务和临时数据库上复跑了 5 项现有断连/重启/清理测试，全部通过；没有关闭真实 DSH、停止 NoneBot 或断开 QQ 来制造故障。模拟结果与代码检查支持上述行为说明，不代替未来对其他故障类型的验证。

## 保持 QQ 在线的测试与部署

**测试期间不停止、重启或另开一个生产机器人，不断开现有 OneBot WebSocket，也不重启生产 DSH、NapCat 或 QQ 客户端。只在正式实装后重启需要加载变更的进程。**

1. 开发与验证在独立目录或临时状态上进行。离线测试使用模拟消息收发和临时数据库，HTTP/WebSocket 协议测试使用动态回环端口，不占用机器人 8080 端口。不要用第二次 `nb run` 做测试。
2. 验证已部署预设的真实 DSH 联调可以新建独立测试会话，使用内存中的发送函数；不得调用生产群的 `ai 重置`、停止现有群会话或发送测试消息。仅做文档修改时检查链接和配置说明即可，无须重新收费联调。
3. 修改预设或守卫时，先用临时 profile 和安装器测试验证；必须验证运行态新预设时使用隔离测试实例，不为了测试改写生产 profile。无法隔离时先完成离线检查，将切换留到正式部署。
4. 正式上线前备份 SQLite 和相关配置，等待正在运行的 AI 回合完成。只改 Python 插件或 `.env.agent_chat` 时重启机器人；修改 DSH 预设/角色卡时再按安装流程重启 DSH，并处理需要更新的群映射。NapCat 和 QQ 客户端保持运行。
5. 上线后检查插件加载、允许群数量、QQ 网关重新连接和 DSH 安全预设；没有换人设/预设时保留原有会话。出错时用已保存的提交与配置备份回退，避免将运行中数据库无差别覆盖为旧快照。

自动修改 DSH 配置时使用兼容 YAML 1.2 的解析器，验证除目标字段外所有值保持不变，尤其不要把字符串 off 转成布尔值。发布恢复流程应单独保障 NoneBot 重新启动，不能因 DSH 启动超时而跳过机器人恢复。重定向日志前设置 PYTHONIOENCODING=utf-8，避免 emoji 在 Windows 默认编码下写入失败。

日常新增群只需改私有白名单并在配置正式应用时重启机器人。修改 Markdown 说明文档不需要重启任何进程。

### 按来源群汇总黑话，集中审核

在机器人所在的审核群发送 `ai 黑话`，即可得到**一份原生 QQ 合并转发**。该群不必在 `AGENT_CHAT_GROUPS` 中，但发送命令的人必须是 NoneBot `SUPERUSER`，普通群主/群管理员不会自动获权。词条按来源群号分组，每个群单独成节点，长组再拆多段；每段按累计学习次数降序，显示全局编号、状态、释义草稿、用法、例句、风险及简短公开来源。节点由机器人自身发送，不伪造群友身份，不附带原聊天或发言者身份字段。长用法/例句及过长或过多的来源链接会省略，释义与风险保留存储范围内的完整文本。

默认“高频”为累计学习次数至少2次，包含候选、已确认和已拒绝。`ai 黑话 候选` 只看待审高频词；`ai 黑话 候选 全部` 也包含只记录过1次的候选；`ai 黑话 全部` 还显示无来源记录的共享手工词条。这里的频率来自现有学习记录，**不是所有群消息的实时词频统计**：没有被学习器提取的发言不计入，已确认词的原有累计次数可能不再增长；每群显示的是受留存上限影响的来源记录条数。

每次最多10个转发节点（1个说明节点 + 9个分组段），每段最多1800字符，不再把超出词条直接截断。超过一页会在说明节点给出下一页命令，例如 `ai 黑话 候选 全部 2`；一次只发送请求的这一页。没有符合条件的词、页码错误时只返回一条简短说明。网关失败或超时不自动重发，也不回退成大量普通消息。节点编码与 `their_ana.AnaList` 的 SAA 适配一致：获取真实机器人昵称，构造聚合 `Message`，正文作为字面文本。另显式设置 NapCat 的 `source/news/summary/prompt`，卡片预览只包含固定说明及页数、词条数，完整词条保留在展开后的节点中。本机 NapCat 默认预览会复制所有节点的全部正文，长汇总因此可能上传成功但卡片发送失败；当前 SAA 聚合发送器不能传入这些预览字段，所以这里直接调用同一个 OneBot 合并转发接口。整条发送流程上限60秒，底层各 API 仍受适配器超时限制；日志记录异常类型和返回码，不记录词库正文或凭据。

同一词在多个来源群出现时，在各组分别展示但共用同一个编号和词义；确认一次后仍按现有设计供所有 AI 群使用。来源包含当前机器人已保存的历史群记录，不因某群后来移出 AI 白名单而丢失审核入口；其他机器人账号的私有候选不会出现在本账号报告或被跨账号确认。

在这个审核群直接发送 `ai 黑话确认 12 15 18`、`ai 黑话拒绝 12`、`ai 黑话删除 12` 或 `ai 黑话添加 词语 | 解释` 即可管理词库。这些操作只读写本地数据库，不调用 LLM、不消耗模型 token。它们不会把审核群加入 AI 白名单，不建立 DSH 群会话、不收集该群聊天，也不放开其他群的记忆、恢复或重置管理。

### 批量确认黑话

仅 SUPERUSER 可以确认。可在任意机器人所在群（包括未启用 AI 的群）使用全局编号审核该机器人收集的各群词条和共享手工词条。`ai 黑话确认 12 15 18` 使用每条词语各自已有的研究解释；保留逗号、顿号和 `#12` 格式兼容。每次最多30条，重复编号会去重。

需要分别补解释时，可在同一条 QQ 消息中发送：

```text
ai 黑话确认
12 | 第一条的解释
15 | 第二条的解释
```

单条旧用法 `ai 黑话确认 12 解释` 继续支持；纯数字解释请用 `12 | 233`，避免与多个编号混淆。结果会列出成功和未确认的编号。没有解释、不属于当前机器人来源范围或解释不合要求的词条会跳过，不影响其他有效词条；不会把一份解释批量复制给不同词语。格式错误、重复编号解释冲突或超过30条时整条命令不执行。

| 诊断代码 | 处理方式 |
| --- | --- |
| `safe_preset_missing` / `unsafe_preset_composition` | 检查是否装在当前 profile、是否重启、是否被额外插件改变 |
| `dsh_auth_failed` / `dsh_auth_expired` | 刷新私有配置的 DSH 凭据并重启机器人 |
