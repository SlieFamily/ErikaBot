# agent_chat：NoneBot ↔ DSH 安全角色聊天

NoneBot 负责 QQ 收发、白名单、消息仲裁与限流；DSH 负责模型/API Key、人设、会话持久化与上下文压缩。插件默认关闭。模型凭据只保留在 DSH 内，机器人仅持有本机 DSH 连接凭据。

当前实现面向 Harness **0.2.1-rc.2** 的 slash RPC 与 `remote.mux` 协议（DSH Desktop 2.0.18 内置该版本）。未知响应、缺少安全预设或不支持的接口会停止处理，绝不降级到普通智能体。升级 DSH 后应重新联调。

## 功能与消息优先级

- 默认只响应白名单群内的 @、对机器人的引用回复，以及白名单私聊。普通群聊进入有限本地上下文；将 `AGENT_CHAT_AMBIENT_PROBABILITY` 从 0 调高可允许概率接话，上限 0.2。
- 每个“机器人账号 + 群号/私聊用户”独立绑定一个 DSH 会话，重启复用，避免串群。SQLite 存在 `data/agent_chat/state.sqlite3`，每个对话最多保存 200 条输入；首次补充最近 20 条，以后每次只补充尚未送入 DSH 的最新消息，单次上限仍是 20 条。
- 现有显式命令优先。`their_ana.SuperAna` 和 `abuse` 标记为被动处理器：实际发出语录才占用消息。普通消息扫描后不吞掉 AI 机会；默认 @ 时由 AI 接管，关闭 `AGENT_CHAT_TAKEOVER_MENTIONS` 可保留旧 @ 语录行为。
- AI 在 NoneBot 的事件后处理阶段调度，因此不会被 SuperAna 的 `block` 阻断。对 their_ana 的修改不引用 AI 服务，AI 关闭时保留旧行为。
- 同群串行、2 秒合并、8 秒冷却，每小时每个对话最多 30 次调用；最多 2 个模型请求并发、16 个待处理对话。默认回复最多 600 字符。
- 收到旧消息快照不重发；输出只认本次请求对应的已完成回合，忽略流式片段和思考内容。断线、超时或发送结果不确定时暂停该会话，不自动重试，避免重复回复和重复收费。
- 超级用户命令：`ai 状态`、`ai 恢复`、`ai 重置`（也接受 `/ai`，以机器人 COMMAND_START 为准）。重置先清空 DSH 待处理消息并取消执行，再清除当前对话的本地映射与上下文；保留 DSH 历史和调用频率记录。

支持文本聊天、可选读图、随机接话和安静时的自主发言。语音和视频目前仍只有类型占位符；语音识别按用户要求延期。可选联网搜索通过 DSH 原生 AnySearch 工具，模型自主决定是否查询；DSH 仍未开放任意文件处理、MCP 或多智能体工具。

### 哪些消息会让她开口

以下规则均先经过白名单、自身消息过滤、去重、旧消息检查和已有插件仲裁：

| 场景 | 是否安排模型调用 | 可能不发言的原因 |
| --- | --- | --- |
| 群内 @ 机器人、引用机器人自己的消息 | 不经过随机概率和夜间静默门槛 | 命令已处理、调用额度、会话暂停、错误、模型 `[SILENT]` 或过滤后无正文 |
| 白名单私聊 | 按直接对话处理 | 同样受冷却、调用额度、会话状态及沉默控制 |
| 普通群消息 | 非安静时段按 `AGENT_CHAT_AMBIENT_PROBABILITY` 抽签 | 配置值是调度概率，最终回复率还受模型判断及其他限制影响 |
| 只发图片，没有 @ | 可进入近期上下文；随机接话触发时可能看图 | 不会每张图片立即调用模型；之后的文字触发也可带入近期图片 |
| 群内安静达到阈值 | 定时检查合格群，安排一次自主发言机会 | 无新活动、当天额度用完、无人回应、夜间、模型选择沉默或生成期间有新消息 |

模型在直接对话、随机接话和自主发言路径都可以输出 `[SILENT]`。当前没有独立的“先判断要不要回复”模型调用；抽签命中后才调用 DSH，由同一轮决定回复或沉默。固定 2 秒消息合并属于去抖，不等于模型自主等待群友把话说完。

模型明确输出 `[SILENT]` 才视为主动沉默。如果确认回合已结束，却没有最终正文（例如服务商只返回 `reasoning` 块），直接 @、引用和允许的私聊会收到一条简短失败提示；随机/主动发言仍保持安静。内部搜索控制输出无法作为答案发布时也适用此规则。不会把思考块或其标签后面的文字提升为答案，也不会因此自动重复模型请求。断线、超时及发送结果不确定仍走暂停保护，不能用此规则绕过。

@ 判定会检查原始消息中的结构化提及，避免 OneBot 在处理“引用别人的图片 + @机器人”时删掉 @，使直接提问误走夜间静默或随机路径。消息中间的真实 @ 也有效；@其他人、@全体和文字形式的 CQ 码不会被视为 @机器人。

### 当前部署节奏与仓库默认值

当前私有配置的节奏是：随机接话 5%；安静 15 分钟后可主动说一句；每群每天最多 6 次主动尝试。2026-10-26 部署核对时保留了用户当前的 5% 设置，并按要求取消夜间静默，随机与自主发言全天可触发；冷却、等待回应和次数额度仍然生效。主白名单由私有配置维护，目前部署到 5 个群，各群会话独立且共用同一版人设。仓库不保存完整生产白名单或登录凭据。

仓库示例默认仍关闭插件、读图、自主发言，随机概率为 0，需按实际用途启用。`AGENT_CHAT_PROACTIVE_GROUPS=[]` 表示沿用主白名单；主白名单新增群后重启机器人即可，群会话会按需建立。已有群不会因追加群号而丢失记忆。

| 常用参数 | 默认值 | 用途 |
| --- | --- | --- |
| `AGENT_CHAT_FORWARD_PERSONA` | `true` | 首次完整载入、后续短提醒；关闭只影响对话里的角色投递，不关闭预设校验 |
| `AGENT_CHAT_CONTEXT_MESSAGES` | `20` | 首次或单批新增输入的最大消息数；超过上限只取最新消息 |
| `AGENT_CHAT_DEBOUNCE` / `AGENT_CHAT_COOLDOWN` | `2` / `8` 秒 | 合并同群短时消息并限制调用节奏 |
| `AGENT_CHAT_MAX_CALLS_PER_HOUR` | `30` | 每个对话共用的调用额度，包括随机、自主、沉默和失败尝试 |
| `AGENT_CHAT_MAX_CONCURRENT` / `AGENT_CHAT_MAX_PENDING` | `2` / `16` | 模型并发数及正在处理或排队的对话数上限 |
| `AGENT_CHAT_TIMEOUT` / `AGENT_CHAT_MAX_REPLY_CHARS` | `90` 秒 / `600` 字符 | DSH 回合超时和最终可见回复长度 |

各参数完整定义见 [配置模型](../src/plugins/agent_chat/config.py)，建议从 [.env.agent_chat.example](../.env.agent_chat.example) 开始设置。

## AI 自主联网搜索（AnySearch）

搜索完全交给 DSH 已安装的 `@anysearch/anysearch-dsh`（本机 0.1.8）。模型在同一个 DSH 回合里自主调用原生 `web_search`，阅读工具结果后再生成最终群聊回复。Python 只负责消息桥接、搜索授权、用量记录和输出过滤，**不请求 Bing/搜狗、不解析搜索网页、不再发送两轮 JSON 搜索协议**。

在 DSH 的当前 profile 安装并启用 AnySearch，将 `web.searchProvider` 设为 `anysearch`，再安装本项目更新后的安全预设。首次迁移须重启 DSH 与 NoneBot；之后仅改以下开关只需重启 NoneBot：

```dotenv
AGENT_CHAT_SEARCH_ENABLED=true
AGENT_CHAT_SEARCH_AMBIENT=false
AGENT_CHAT_SEARCH_PROACTIVE=false
AGENT_CHAT_SEARCH_MAX_PER_HOUR=6
# 同一原生回合可能包含多段模型推理，当前部署给出 300 秒总预算。
AGENT_CHAT_TIMEOUT=300
```

当前全部 5 个白名单群沿用这组开关。默认只有 @、引用机器人和允许的私聊可以搜索；随机接话与主动发言默认没有搜索授权。是否需要查询由模型判断，普通闲聊不会因为开放能力就必然调用搜索。无需专门搜索命令，例如“帮我搜一下明日堇sumire是谁”。专名应保持完整，资料无关或不足时明确无法确认，不能从空结果推断名字写错或人物不存在。

### 次数、费用与输出

- 每个 DSH 回合最多执行 **2 次 `web_search`**，每次仅 1 个至多 120 字符的公开主题、最多 3 条来源。模型可在第一次结果不足时调整关键词再查；原生工具每次超时 20 秒，整个 DSH 回合仍受 `AGENT_CHAT_TIMEOUT`（代码默认 90 秒，当前部署 300 秒）约束。原生工具会把多段模型推理合并进一个回合，慢模型可能需要增加总预算；这不是取消超时，也不代表通常需要等满 300 秒。
- 每个“机器人账号 + 群/私聊”每小时最多 6 个实际尝试搜索的回合。首次工具调用即记一次，失败和空结果也计数；普通未搜索回合不消耗搜索额度。重启 NoneBot 或 `ai 重置` 不返还额度。每群串行、总并发仍由原有机器人限制控制。
- 原来的每小时 30 次额度现在统计 **DSH 回合**，不等于模型底层请求次数。一个原生工具回合内可能包含多次模型推理与工具结果阅读，仍会产生 token 费用。人设首次/压缩后投递和群聊增量发送保持不变。
- AnySearch 凭据由 DSH 管理，不写入机器人的配置。未配置时插件可使用匿名访问，但能否成功、配额和收费取决于 AnySearch 当前服务。不要将聊天 API Key 复制给搜索服务。旧 `AGENT_CHAT_SEARCH_TIMEOUT` 已不再使用；搜索超时由安全预设中的 `searchTimeoutMs: 20000` 固定并验证。
- 桥接只接收当前请求、当前回合的最终文本；不会发送“我去查查”等中间消息、工具结果原文、思考块或伪工具调用标签。旧 `agent_chat_search` / `QQ_SEARCH_RESULT` 文本也会拦截。只有实际工具结果元数据中的公开来源网址可作为本次搜索的引用，最多 2 个，最终回复仍受 600 字符默认上限约束。
- Python 不再维护搜索网页缓存。查询与工具结果会随 DSH 会话保留；不要把会话历史当作普通日志公开。

### 执行边界与失败处理

安全预设只声明受限 `web_search`，每个真实 agent 建立时只允许继承该工具，其他工具全部隐藏并由执行守卫拒绝。`web_fetch`、AnySearch 高级/批量工具、shell、文件、MCP、子智能体和 `run_code` 均未开放。搜索 Provider 必须保持 `anysearch`，切换到其他 Provider 会被拒绝。

每次 NoneBot 请求的首行由桥接生成控制头，绑定本次会话、请求 ID、搜索开关和有效期。DSH 守卫只从当前回合真正的用户消息首行读取它；QQ 群消息被包在后面的数据中，模型输出、网页结果和历史控制头不能授予权限。普通 DSH 手动会话输入缺少该控制头也不能使用这个桥接预设搜索。

执行前拒绝空白/过长关键词、常见 QQ/手机数字串、邮箱、路径和凭据关键词，提示词另禁止搜索群友私人资料。规则不能识别所有语义上的隐私；不要把敏感信息当作公开主题。实际请求和凭据处理由 AnySearch 插件负责，本桥接不再承诺旧 Python 下载器的 DNS 固定等行为。网页文字始终视为不可信资料，不能据此解除工具限制。

普通搜索错误作为工具结果交给模型解释，不会单独暂停会话；若 DSH 断线、回合失败或工具事件不匹配，仍暂停并尝试取消旧请求，不自动重试。只有最终正文才发送 QQ。`ai 状态` 显示开关与最近一小时搜索回合数，不是实时搜索服务健康检查。

### 安装迁移注意

本版预设从三个模块变为四个：执行守卫、人设、隔离的历史压缩、仅搜索的原生 Web 工具。预设指纹会改变，不能直接放行旧指纹。保留旧记忆的迁移应先备份，再核对每个会话的原预设、结束回合、空队列及没有待发送结果，逐项更新已验证的映射并让人设在下一轮重新载入；不要直接清空数据库或无条件取消全部暂停。

安装器会更新 package.json 和按内容哈希存放的预设链接，但不自动同步 pnpm 锁文件。若 profile 已有 `pnpm-lock.yaml`，备份后在该 profile 执行 `pnpm install --lockfile-only --offline --ignore-scripts`，核对变更与已安装插件和新预设一致，再重启 DSH。依赖不齐导致离线失败时先排查。否则后续依赖维护可能把链接恢复到旧预设；`Preset services require isolate realms: compaction` 就可能来自误加载缺少压缩隔离的旧版本，不能关闭校验来绕过。

## 配置与安装

1. 在 DSH 配置模型并确认普通聊天成功。Desktop 使用兼容模式，开启“浏览器访问”，网络范围保持“仅本机”。普通 HTTP 请求返回 403 时应先检查这一设置。不要提取或伪造桌面内部 renderer capability 来绕过它。
2. 将专用预设安装到**运行中的那个 profile**。例如 Windows Desktop 的 profile 通常是 `$HOME/.dsh/profiles/desktop`；服务器 Web profile 通常是 `~/.dsh/profiles/web`。先预览，再应用：

   ```powershell
   node scripts/setup_agent_chat_dsh.mjs --profile "$HOME/.dsh/profiles/desktop"
   node scripts/setup_agent_chat_dsh.mjs --profile "$HOME/.dsh/profiles/desktop" --apply
   ```

   安装器保留已有依赖及 bundles，备份 package.json，并将守卫与预设复制到 profile 下按内容哈希命名的目录，再创建模块链接。切换 Git 分支不会改变已部署守卫。不会安装网络依赖、启动进程、删除历史或修改模型配置。应用后重启 DSH；若 profile 管理器要求安装依赖，按该版本 DSH 的插件安装流程操作。

3. 在项目根目录创建私有配置：

   ```powershell
   Copy-Item .env.agent_chat.example .env.agent_chat
   ```

   填写准确的 `AGENT_CHAT_DSH_URL`（Desktop 当前监听端口可能不是 3080）、白名单群号、DSH 登录链接里的 token 或有效的 `dsh-auth-*` Cookie。两种连接凭据选一种。不要把 LLM API Key 当作 DSH 登录 token。不要将凭据写入本仓库已跟踪的 `.env.prod`，也不要粘贴到群内。

   插件自动读取 `.env.agent_chat`；优先级为进程环境变量 > 此私有文件 > NoneBot 配置 > 默认值。私有文件禁止 `${...}` 插值，防止意外改变凭据。`AGENT_CHAT_PROVIDER` / `AGENT_CHAT_MODEL` 同时留空则使用 DSH 默认模型，也可成对填写以固定模型。

   远程服务器通过 SSH 本地转发接入，例如 `ssh -N -L 3080:127.0.0.1:3080 user@server`，插件 URL 仍使用 `http://127.0.0.1:3080`。插件仅允许字面量回环地址，HTTP 和 WebSocket 均拒绝重定向，不向任意域名转发凭据。

4. 检查真实 DSH：

   ```powershell
   poetry run python scripts/check_agent_chat.py
   poetry run python scripts/check_agent_chat.py --smoke
   ```

   第一条只校验认证与实际预设组成；第二条新建独立 DSH 会话，调用模型一次（产生费用），确认请求与回包对应并清理待执行任务。不会给 QQ 发消息，也不会改已有会话。该诊断会话的历史保留在 DSH。

5. 确认通过后设 `AGENT_CHAT_ENABLED=true`，保留明确白名单，然后 `poetry run nb run`。修改配置后重启机器人。默认人设位于 [roles/古户绘梨花.md](../roles/古户绘梨花.md)，安装器会将其作为纯文本嵌入安全预设；也可用 `--role "roles/我的角色.md"` 选择其他文件。修改人设后重新安装并重启 DSH，旧映射会要求 `ai 重置`。完整的换卡、回退和群配置步骤见 [角色设置说明](../roles/README.md)。

各项能力的当前状态见 [后续计划](agent_chat_roadmap.md)。

## 人设的实际投递

默认 `AGENT_CHAT_FORWARD_PERSONA=true`：DSH 系统预设保留完整角色卡；桥接在每个会话首次使用时，另外将同一次已校验预设中的完整角色提示送入对话。后续普通轮次只发送短提醒和新增群聊 JSON，不再逐轮追加完整卡片或重复最近 20 条消息。@、随机接话、自主发言和图片问答共用这条路径。不会从群消息、昵称或本地尚未安装的角色文件拼接管理员人设，不转发凭据或插件配置。

人设载入状态与消息进度按群持久化，机器人重启后继续使用。检查 DSH 的持久事件发现历史压缩或重写、无法确认历史连续性时，会保守补发完整人设；发生在当前生成期间的压缩会在下一次请求检查并补发。只有 DSH 明确完成的请求才推进进度，模型选择 `[SILENT]` 也算已读取。网络故障仍暂停会话，不盲目重试。新建、明确丢失后重建或重置的会话会重新初始化；从旧版升级首次运行会补发一次，并保留原会话及记忆。

这是减少重复累积，**不代表后续 API 请求不再计算人设或历史 token**：DSH 仍向模型提供系统提示与会话上下文，缓存是否命中及实际计费取决于模型服务。近期图片引用的查找规则保持不变；图片仍可能随后续相关请求再次附带，本次优化不声称消除图片费用。

三个连续测试回合向 DSH 新增的文本分别约为 **9830、542、544 个字符**：第一次包含完整角色，之后只带短提醒与新消息。该抽查同时验证了人物别名和重建 Python 客户端后的记忆。字符量随聊天内容变化；生产中的历史会继续由 DSH 压缩，并不等同于永久、逐字无损的长期记忆。

完成一轮生成后只推进该轮开始时截取的消息边界，生成期间新到的消息留给后续轮次。发送到 QQ 失败时不自动重发；增量记录保留在本地 `delivery` 表，按群与 DSH 会话绑定。自动压缩的内部检查点经过关联验证后处理，避免被误判为外来对话而暂停；真正的并发外来输入仍会暂停。

2026-10-25 的真实抽查发现，当前模型只用系统预设时未稳定遵循人设，所以保留首次对话载入与短提醒。换用能稳定遵循系统人设的模型后，可将该选项设为 `false`，仍保留预设校验、增量聊天与执行端工具守卫。原 qq-bridge 也不是所有路径逐轮注入：v1 的活跃批处理可只发新增消息；v2 可以通过工具读取完整卡片。本桥接不会为省 token 开放角色文件读取工具；搜索使用独立的最小权限规则。

换卡仍需安装并重启 DSH、重置旧群映射，详见 [角色说明](../roles/README.md)。群会话各自独立；更新所有群时先备份本地 SQLite，再停止旧会话、使用同一版预设建立新映射，旧 DSH 历史保留。角色剧情中的“主人”和姓名别名不授予任何管理权限。

## 读图

设置 `AGENT_CHAT_IMAGES_ENABLED=true` 并重启机器人。支持同一消息、引用以及最近 10 分钟群聊上下文里的图片，每次最多选择最近 2 张。仍遵守 @、引用回复、随机概率、其他插件优先级和调用限流，不会见图就调用模型。

DSH 模型必须实际支持视觉输入。自定义模型未声明输入类型时，DSH 会默认为纯文本；在对应模型条目添加 `input: [text, image]` 后重启 DSH。这个声明不会让纯文本模型获得视觉能力，须实际验证：

```powershell
poetry run python -B tests/agent_chat_image_probe.py --confirm-model-call
```

脚本用不含用户信息的几何图调用模型一次，不发送 QQ 消息。本机 `steinsgate / deepseek-v4-flash` 补充输入声明后已正确识别形状和颜色，没有更换 API Key 或默认模型。

仅从允许对话的结构化 `image` 消息段取图，文本中的任意链接不会被抓取。下载只允许 QQ 图片 CDN：`qpic.cn` 及子域、`multimedia.nt.qq.com`、`multimedia.nt.qq.com.cn`、`gxh.vip.qq.com`。全部 DNS 地址须为公网；固定已校验地址进行连接，保留原主机 TLS 校验，拒绝重定向，不转发 DSH 凭据。图片 URL 的临时授权参数不会写入模型提示或 HTTP 日志。

默认单图输入上限 8 MB、2000 万像素；校验 PNG/JPEG/WebP/GIF 后转成最大边 1536 像素、最多 1 MB 的 JPEG，并去掉元数据。动态图只取首帧。模型服务会收到处理后的图片；Base64 不会作为普通文字发给模型，原始下载字节不单独落盘，DSH 会按自身机制保存附件。

URL 获取失败时，可通过安全缓存标识调用 [OneBot get_image](https://github.com/botuniverse/onebot-11/blob/master/api/public.md#get_image-获取图片)。默认不读取本地路径；只有网关返回本地缓存且没有 URL/Base64 时，才需要将具体图片缓存目录填入 `AGENT_CHAT_IMAGE_CACHE_ROOTS`，不要填写整块硬盘或用户目录。

下载或校验失败会明确标记“未取得图片”。DSH 若明确在接纳请求前拒绝图片，可改发一次纯文本说明；不会将断线、超时等不确定错误当作可重试条件。语音尚未接入，不能理解语音内容或音色。

## 随机接话与自主发言

用户选定的活跃配置如下，仓库示例默认仍保持关闭：

```dotenv
AGENT_CHAT_AMBIENT_PROBABILITY=0.05
AGENT_CHAT_PROACTIVE_ENABLED=true
AGENT_CHAT_PROACTIVE_GROUPS=[]
AGENT_CHAT_PROACTIVE_IDLE=900
AGENT_CHAT_PROACTIVE_DAILY_LIMIT=6
AGENT_CHAT_QUIET_START=0
AGENT_CHAT_QUIET_END=0
AGENT_CHAT_UTC_OFFSET_HOURS=8
```

- 普通消息当前有 5% 的调度概率；被已有命令或语录回复占用时不接话，@ 和引用机器人无需抽签。随机消息不会覆盖排队中的 @ 请求，概率不保证固定条数内必回。
- 每 30 秒检查已连接机器人的白名单群。最近 6 小时内有新群消息，且距最后群消息和 AI 发言均已安静 15 分钟，才有一次主动发言机会。启动后至少等待 60 秒；私聊不主动开口。
- 一次机会最多一句，模型可以沉默。一轮安静期间只尝试一次，没有新群友消息就不继续；新群消息到来后重新计时。生成过程中有新消息，旧的主动回复会被丢弃。
- 每群每天最多 6 次主动尝试，沉默和失败也占一次，避免模型反复空转。次数与等待回应状态存入 SQLite，重启和 `ai 重置`不会清空当天额度。
- 当前起止小时均设为 0，全天不设安静时段。仓库默认仍为 23:00—次日 09:00；需要夜间静默时可恢复该配置。@、引用回复始终不受夜间时段限制。
- 共用原有每小时调用上限、冷却与并发限制。`AGENT_CHAT_PROACTIVE_GROUPS=[]` 沿用主群白名单；填写群号可缩小范围，不能超出主白名单。

修改后重启机器人。`ai 状态` 显示读图、随机概率、自主发言及当日次数。分别设置 `AGENT_CHAT_PROACTIVE_ENABLED=false`、`AGENT_CHAT_AMBIENT_PROBABILITY=0` 可关闭主动发言和随机接话。

## 思考标签过滤

独立思考块继续忽略；正文里的 `<think>`、`<thinking>`、`<analysis>`、`<reasoning>` 连同包裹内容，在 QQ 发送前移除，再截断长度。只有结束标签时，之前的可疑内容也丢弃；未闭合的思考段不发送。支持大小写、嵌套和 HTML 转义标签。过滤后没有正文时，直接提问收到固定失败提示，随机/主动发言保持沉默；模型明确的 `[SILENT]` 仍不发言。这是对已识别结构的防护，不声称能判断任意无标记文字的用途。

## 安全边界

`dsh/agent-chat/guard.mjs` 在 DSH 执行端注册单调拒绝守卫，并在 agent 创建时设置只含 `web_search` 的白名单。搜索还必须通过本轮授权、公开参数及次数校验；shell、文件、MCP、子智能体、插件安装和未来未知工具均被拒绝。守卫 API 不支持、Provider 不匹配或作用域不正确时直接失败，不降级到普通智能体。

桥接每次请求读取**实际**预设组成，固定要求守卫、人设、隔离的上下文压缩和受限原生 Web 搜索这四项。人设关闭可选运行环境上下文，不接受模板表达式。群聊内容封装为 JSON 数据，斜杠命令不会成为 DSH 控制命令；不转发审批、设置变更或任意 RPC。QQ 发送只创建文本、经校验的引用和有限 QQ 自带表情段。模型输出的 `[CQ:...]` 仍作为文字，不会成为图片、@全体或文件操作。

人设使用 DSH 的 `complete: true`，让固定聊天规则和所选角色卡组成完整系统提示，避免继承通用编程助手的身份章节。`includeRuntimeContext: false` 抑制可选运行环境上下文；DSH 的必需上下文仍可能存在，不能将其视为完全隐藏主机元数据的保证。完整提示模式不解除工具守卫。

提示词不能保证模型永不被带偏；这套限制的目标是让带偏的对话无法通过工具操作主机。它依赖可信的 DSH 实现、守卫代码和宿主插件，并非操作系统沙箱。不要给 QQ 专用预设混入未审计插件，不要在桥接管理的 DSH 会话中同时手动聊天或切换预设。服务器部署宜使用独立低权限账号及独立 DSH profile。

连接 Cookie 权限较高，只在本机私有配置中保存。插件不会将它、模型 Key 或服务错误详情发送给模型/QQ；不要开启包含原始协议或请求头的调试日志。允许群的文本与有限图片引用元数据会保存到本地；文本和成功取得的图片可进入 DSH 并发送给所选模型服务。禁用插件后停止记录；既有历史需由管理员按需要清理。

## 运行进程与日志

Windows 上用 `poetry run nb run` 启动后，会出现 Poetry、nb 和 Python 的父子进程。实际提供 NoneBot/OneBot 服务的是监听配置端口的 Python 进程；不能只看任务管理器中任意一个 `python.exe`。PID 会随重启变化，查当前进程可在另一个 PowerShell 窗口运行：

```powershell
$botListener = Get-NetTCPConnection -LocalPort 8080 -State Listen
$botListener | Select-Object LocalAddress, LocalPort, OwningProcess
Get-CimInstance Win32_Process |
  Where-Object { $_.ProcessId -in $botListener.OwningProcess } |
  Select-Object ProcessId, ParentProcessId, Name, ExecutablePath
```

8080 是本部署的 NoneBot 端口，其他部署按实际配置替换。DSH Desktop 是独立进程，界面进程与监听本机 API 端口的子进程可能不同；其窗口关闭是否等于退出，要以端口是否还在监听为准。DSH、NoneBot、NapCat/QQ 不是同一个进程。

本机 2026-10-26 部署使用后台启动并重定向输出，日志目录为用户目录下的 `Documents/Codex/2026-10-24/new-chat/work/agent-chat/social-release/`：

- `bot.stdout.log`：标准输出，包含 NoneBot 启动、插件加载和网关连接等日志。
- `bot.stderr.log`：标准错误，可能包含警告和错误；文件为空不代表没有发生过业务问题，应同时检查标准输出和 `ai 状态`。

这些文件是本次启动的日志，不是跨所有历史部署的统一日志目录。旧启动可能写入其他目录；日志更新时间也不能单独作为服务是否存活的依据。当前没有启用 `bot.py` 中注释掉的文件日志处理器，也没有内置日志轮转、自动清理或“一键导出”命令；已经重定向的日志可以直接查看和复制。

查看当前日志末尾（`-Wait` 可选；在独立查看窗口按 Ctrl+C 只结束查看）：

```powershell
$logDir = Join-Path $env:USERPROFILE 'Documents\Codex\2026-10-24\new-chat\work\agent-chat\social-release'
Get-Content -LiteralPath (Join-Path $logDir 'bot.stdout.log') -Tail 100 -Wait
```

导出已有日志不会断开机器人连接，也不需要重启：

```powershell
$logDir = Join-Path $env:USERPROFILE 'Documents\Codex\2026-10-24\new-chat\work\agent-chat\social-release'
$exportDir = Join-Path $env:USERPROFILE ('Desktop\ErikaBot-logs-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $exportDir | Out-Null
Copy-Item -LiteralPath (Join-Path $logDir 'bot.stdout.log'), (Join-Path $logDir 'bot.stderr.log') -Destination $exportDir
```

桥接自身只记录固定错误代码，不把模型内容、认证头或远程错误正文写入错误日志；其他插件和框架日志仍可能包含 QQ 号、聊天内容等信息。对外提供前检查并脱敏，不把 `.env.agent_chat`、DSH 凭据文件或会话数据库当作普通日志一并上传。

今后正式启动时可以统一保存到已被 Git 忽略的 `data/agent_chat/logs/`。以下命令只在原机器人已经正常退出、准备正式启动时使用，不要为了收集日志再开第二个机器人：

```powershell
Set-Location 'E:\rerika\ErikaBot'

New-Item -ItemType Directory -Force -Path $logDir | Out-Null
$stamp = Get-Date -Format 'yyyyMMdd-HHmmss'
$stdoutLog = Join-Path $logDir ("bot-$stamp.stdout.log")

poetry run nb run 1>> $stdoutLog 2>> $stderrLog
```

不同启动使用不同文件名以保留旧日志；这仍是输出重定向，不是自动轮转或进程托管。

## 更换 API、Key 或模型

先区分两层连接：**NoneBot → 本机 DSH** 使用 `.env.agent_chat` 的 URL/Cookie；**DSH → 模型服务商** 使用 DSH 中配置的 API 地址、模型和 Key。更换模型 API 不等于更换 DSH 连接凭据。

| 变更位置 | NoneBot 是否需要重启 | 会话与生效注意事项 |
| --- | --- | --- |
| 只在 DSH 更换同一服务商的模型 API Key | 通常不需要 | 等当前回合完成；按 DSH 的保存/加载机制生效，必要时仅重启 DSH。Key 不在本地会话绑定指纹中 |
| 在 DSH 更换模型 API 地址、模型或默认路由 | 通常不需要，仅改 DSH 即可 | 先核对协议、模型能力和上下文上限；不要假定“更改默认模型”会同时切换所有已有群会话，应检查各会话实际选择 |
| 修改 `.env.agent_chat` 中的 DSH Cookie/登录 token | 需要 | 私有配置启动时加载，没有热重载；仅更换认证凭据本身不会改变策略指纹 |
| 修改插件的 `AGENT_CHAT_PROVIDER` / `AGENT_CHAT_MODEL` 或 DSH URL | 需要 | 它们参与会话绑定指纹；重启加载后，旧群映射会暂停并要求管理员处理，不能自动无缝迁移 |
| 更换 DSH profile、机器或全新实例 | 视连接配置变化决定 | 原会话数据与编号可能不存在；先安排数据迁移，不能只复制 Key 就认为历史已迁过去 |
| 修改角色卡、安全预设或守卫 | 按安装流程重启 DSH；部署时安排必要的机器人切换 | 内容变更触发预设指纹变化，旧群映射须核查后重置或迁移 |

插件中 provider/model 留空时由 DSH 决定模型；成对填写时，插件在创建会话时调用 `session/selectModel`。当前没有自动将 DSH 默认模型切换同步到所有既有会话的功能。直接在 DSH 中更换实际模型/服务地址，也不一定触发桥接的配置指纹变化；仍须主动确认实际路由和兼容性。

**更换模型后重新检查读图声明。** 原模型的 `input: [text, image]` 不会自动继承给新模型。若 DSH 返回 `MODEL_DOES_NOT_SUPPORT_IMAGES`，应先用独立测试确认新服务商/模型确实能识别图片，再为这条模型补充 `input: [text, image]`，在正式切换时重载或重启 DSH。不能仅凭模型名称判断视觉能力；声明也不能让纯文本模型凭空支持读图。若 DSH 拒绝图片，桥接会按文字继续对话，只有问题依赖图片时才说明无法看图，不应让聊天中无关的近期图片干扰纯文字问题。

已兼容 Harness 的 `model-selection / notice` 元数据：管理员切换模型时，运行时插入的通知不会再被误认作其他人抢占输入，也不会发到 QQ。真正来自另一个客户端的聊天输入仍会中止当前请求。请在独立会话测试模型，避免同时在桥接使用的群会话里手动聊天。

建议操作顺序：

1. 记录目前 provider、模型、API 地址及 DSH profile，备份需要改的配置，保留回退方法。备份放在不入 Git、访问权限受限的目录。涉及状态迁移时使用 SQLite backup 接口制作一致快照，不在运行中只复制主数据库文件而遗漏 WAL。
2. 在 DSH 新建独立测试会话验证目标 API 的认证、普通文本、人设、历史承接和图片输入。不要在桥接管理的群会话中手动发送测试问题，也不要改群白名单来绕过隔离。
3. 正式切换时尽量等待当前 AI 回合结束，再在 DSH 修改 Key/API/模型。纯 DSH 变更可以保持 NoneBot 与 NapCat/QQ 在线；如 DSH 要求重启，仅重启 DSH，但此期间 AI 暂时不可用，新请求可能失败。当前没有“只暂停 AI、保持其他插件”的运行时维护开关，不能保证热切换期间零失败。
4. 若同时修改 `.env.agent_chat`，保存后在正式应用配置时重启 NoneBot；单纯更新 DSH 模型 Key 不需要因此重启 NoneBot。
5. DSH 恢复后执行 `poetry run python -B scripts/check_agent_chat.py`，检查认证与安全预设。这个命令不调用模型，不能证明模型 Key 正确；需要模型验证时加 `--smoke`，它只新建独立测试会话、产生一次模型调用，不发 QQ 消息。读图还需单独验证视觉能力。
6. 用 `ai 状态` 查看各群是否暂停。未暂停的会话可在新的合格消息到来时继续；已暂停会话不会因为 Key 修好或重启 NoneBot 就自动解锁，按下面的恢复流程处理。AnySearch 搜索不使用聊天 API Key；更换模型后要在独立会话验证其原生函数调用能力，而不只是能否普通聊天。AnySearch 凭据须在 DSH 中单独管理，不能跨服务商直接复用聊天 Key。

只换 Key 不应为了“使它生效”随意执行 `ai 重置`。该命令会清除当前映射与本地输入，后续创建新 DSH 会话；旧 DSH 历史保留，但不会自动合并进新会话。需要保留原有连续记忆的模型切换，应先备份并进行经过检查的会话迁移；当前没有现成的无损批量切换/自动解除暂停命令。

## 保留记忆的恢复、主动引用与合并转发

### `ai 恢复` 与 `ai 重置`

两者只作用于命令所在群或私聊，均仅允许 NoneBot `SUPERUSERS`，群管理员没有额外权限。

- `ai 恢复`：适用于连接故障修好之后的暂停会话。保留原 DSH 会话 ID、历史、本地记录和次数额度；不会调用模型或补发旧消息。下次新消息触发时继续，人设会补充一次。
- 恢复前必须没有本地正在处理的请求；校验当前预设/模型绑定，清理 DSH 队列并取消残留执行，再读取真实会话记录确认最后回合结束、队列为空且最近用户输入来自桥接。检查失败则保持暂停，不能绕过新的安全预设指纹。
- QQ 发送曾超时、或进程退出时停在发送阶段，会持久记录 `delivery_uncertain`，恢复命令拒绝自动放行。先人工确认发送情况；若选择 `ai 重置`，旧发送记录标记为放弃，额度仍保留，不会重发。
- `ai 重置`：清空当前对话的桥接映射和短期上下文，下次建立新 DSH 会话。旧 DSH 历史仍在，但不会自动继承到新会话。
- `ai 状态` 和“当前未暂停”均不是模型服务健康测试。恢复成功只说明会话可继续，不能保证 API 下一次不超时，也不返还使用额度。

### 主动引用、emoji 与 QQ 自带表情

默认开启 `AGENT_CHAT_REPLY_ENABLED=true` 与 `AGENT_CHAT_FACES_ENABLED=true`。模型可自然直接使用 Unicode emoji；需要引用或 QQ 表情时，由受限输出对象表达选择。引用只接受本轮提供的当前聊天近期真实消息 ID（10 分钟内）；未知 ID、其他群及转发内部节点不能作为引用目标。自主闲置发言不引用旧消息。

当前支持 21 种常见 QQ 自带表情，如微笑、得意、害羞、白眼、偷笑、捂脸、吃瓜等，每条最多两个。也可以只发表情。模型自主决定是否使用，不要求每句都引用或加表情。没有表情图片发送、自动收藏、任意 CQ 解析、@全体、拍一拍或分条发送。

普通正文继续作为纯文本发送；只有校验后的引用与表情字段生成 OneBot 消息段。搜索来源过滤和思考内容过滤仍生效；不合法的内部输出对象不能直接发到 QQ。整个回答仍只发一条，发送结果不确定时不退回纯文本重复发送。

### 阅读合并转发

`AGENT_CHAT_FORWARDS_ENABLED=true` 时，仅在已触发 AI 回合之后展开本轮新增消息或其引用中真实的 `forward` 消息段；不会因为群里出现转发就额外调用模型，也不会依据群友贴出的文字 ID / CQ 字符串去查询记录。普通消息是否触发仍遵循 @、引用、随机接话和插件仲裁。

兼容 NapCat `messages` 数组与标准 OneBot `node` 数组，读取文字、发送者名称、QQ 表情占位及图片。图片走原有受限下载与像素校验，并共用每轮图片数量上限；关闭读图时仍可读转发文字。语音、视频与文件仅标记类型，不假装理解内容。

每轮最多两个外层转发、四次查询、两层深度（外层加一层嵌套）、30 个节点和 6000 字符摘录；单次查询最多 8 秒，总展开预算 20 秒。循环引用去重，超限或失败时明确标记截断/未读取，不发送原始错误或媒体签名 URL。此处限制的是模型输入与处理工作量，OneBot 网关收到完整响应的底层开销仍由网关承担。

转发来源和内容都可能伪造，只作待分析资料，不视为当前群友的新指令或已确认事实。展开内容不单独存成长期词库；进入模型的摘录会按 DSH 会话规则留存。实现按 [OneBot 11](https://github.com/botuniverse/onebot-11/blob/master/api/public.md#get_forward_msg-获取合并转发消息) 和本机 NapCat 接口校验。

以上变更仅修改 Python 插件，部署后重启 NoneBot 即可，无需重装人设或重启 DSH。原有 AnySearch 搜索与工具权限边界保持不变。

## DSH 关闭、断线与恢复

DSH 不在线时，AI 会记录连接/协议错误并保持沉默，通常不会使整个 NoneBot 退出或主动断开 OneBot 连接。语录、RSS 等其他插件仍按各自逻辑运行。启动 `agent_chat` 时也不会立即连接 DSH，因此 DSH 暂未启动本身不会阻止配置正确的 NoneBot 启动。

| 故障阶段 | 当前处理 | DSH 恢复后的行为 |
| --- | --- | --- |
| 尚未取得/校验预设，DSH 就已离线 | 本次尝试标记失败、记录日志、不发 QQ 回复；尚未选择会话，不新设暂停标记 | 原本未暂停的会话可以处理后续新消息；不会立即重放失败请求 |
| 已选定群会话，读取上下文或生成中断线/超时 | 持久化暂停该群，尝试清空 DSH 队列并取消执行；清理无法确认也保留暂停 | 需要管理员核查；不会自动解除暂停或重复调用模型 |
| QQ 发送失败或结果不确定 | 不自动重发，并暂停有关会话 | 先确认是否已发送，避免重复发言 |
| NoneBot 意外退出时存在 `inflight` / `sending` 调用 | 分别标记中断 / 发送结果不确定，并暂停已绑定会话 | 不重放旧请求；发送不确定时拒绝自动恢复 |
| 执行 `ai 重置` 时 DSH 仍离线 | 无法确认清空/取消旧任务，重置失败并保留映射 | 先恢复 DSH，再进行清理；不直接删除数据库来绕过确认 |

上述“失败前是否已经选定会话”是当前实现中的区别，不能简单理解成“任何错误都永久暂停”或“DSH 恢复就一切自动恢复”。失败/沉默尝试也计入调用额度；恢复后若触及每小时限制，仍需等待额度恢复。

恢复步骤：先重新打开原 DSH profile，确认模型服务与连接凭据有效；运行只读诊断；再由超级用户查询相关群的 `ai 状态`。该命令展示保存的会话状态和功能开关，**不是实时 DSH 健康检查**。如果已暂停，可执行 `ai 恢复`，由程序完成下述核查并保留记忆；如果接受改用新会话，可执行 `ai 重置`。不要无条件修改数据库中的暂停标记。

当前已具备异常隔离、超时、并发/频率限制、暂停持久化、队列清理和不确定结果不重发；它侧重避免重复或错发。若进程恰好在 QQ 发送阶段崩溃，`sending` 状态不会自动补发，但目前也没有发送确认对账，不能据此声称端到端绝不丢消息。尚未实现全局故障熔断、自动健康探测与退避恢复、运行时 AI 维护开关、自动重启 DSH 或日志轮转。DSH 故障不会自动启动另一个不受限智能体作为替代。

2026-10-25 文档核验时，在独立模拟服务和临时数据库上复跑了 5 项现有断连/重启/清理测试，全部通过；没有关闭真实 DSH、停止 NoneBot 或断开 QQ 来制造故障。模拟结果与代码检查支持上述行为说明，不代替未来对其他故障类型的验证。

## 保持 QQ 在线的测试与部署

**测试期间不停止、重启或另开一个生产机器人，不断开现有 OneBot WebSocket，也不重启生产 DSH、NapCat 或 QQ 客户端。只在正式实装后重启需要加载变更的进程。**

1. 开发与验证在独立目录或临时状态上进行。离线测试使用模拟消息收发和临时数据库，HTTP/WebSocket 协议测试使用动态回环端口，不占用机器人 8080 端口。不要用第二次 `nb run` 做测试。
2. 验证已部署预设的真实 DSH 联调可以新建独立测试会话，使用内存中的发送函数；不得调用生产群的 `ai 重置`、停止现有群会话或发送测试消息。仅做文档修改时检查链接和配置说明即可，无须重新收费联调。
3. 修改预设或守卫时，先用临时 profile 和安装器测试验证；必须验证运行态新预设时使用隔离测试实例，不为了测试改写生产 profile。无法隔离时先完成离线检查，将切换留到正式部署。

5. 上线后检查插件加载、允许群数量、QQ 网关重新连接和 DSH 安全预设；没有换人设/预设时保留原有会话。出错时用已保存的提交与配置备份回退，避免将运行中数据库无差别覆盖为旧快照。

日常新增群只需改私有白名单并在配置正式应用时重启机器人。修改 Markdown 说明文档不需要重启任何进程。

| `concurrent_session_input` | 检查桥接会话是否被手动聊天或其他程序使用；已关联的自动压缩检查点会正常处理 |
| `session_suspended` / `dsh_turn_timeout` | 检查 DSH 运行情况，确保旧任务停止，再尝试 `ai 恢复`；需要新上下文时用 `ai 重置` |
| `preset_changed_reset_required` | 核查预设、地址和模型变更，再重置该对话 |
| `unexpected_tool_call` | 暂停使用，核查 DSH 守卫是否正确加载，不要放宽限制 |

不自动重发结果不确定的请求。若 DSH 清理失败，重置也会失败并保留映射；先处理 DSH 后重试。`AGENT_CHAT_ENABLED=false` 并重启机器人可立即停用本插件。
